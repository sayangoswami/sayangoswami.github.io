Course Description

Official catalog description:

This course will study the tools, techniques and architectures to provide hardware acceleration of software. Topics include: high-level synthesis, register transfer level descriptions and synthesis, gate and transistor level descriptions, finite state machines, systolic arrays and pipeline architectures. Both Field Programmable Gate Array (FPGA) and custom integrated circuit approaches will be covered. In addition to the application of Electronic Design Automation (EDA) tools, the algorithms they use will be described.

Course focus, Fall 2026:

This course introduces the architectures and programming models behind modern General-Purpose Graphics Processing Unit (GPGPU) computing. As the demand for computational throughput has outpaced what traditional single-core processors can deliver, GPUs have become the engine behind machine learning, scientific simulation, and real-time graphics. Acceleration teaches you to think and program in parallel - shifting from the “one instruction at a time” model of introductory programming to orchestrating thousands of threads working simultaneously on the same problem. The course uses Python and industry-relevant GPU frameworks (Numba CUDA, CuPy, PyTorch) throughout, delivered via Google Colab, so no prior experience with systems languages is required.

Course Learning Outcomes

Official catalog outcomes:

Upon completion of the course, students will be able to:

  • Design accelerators for algorithms as demonstrated by creating an accelerator using high-level synthesis and FPGAs.

  • Explain algorithms by explaining aspects of the acceleration process to non-experts.

  • Create a written opinion on a technical subject as demonstrated by writing an analysis of a classic paper on hardware architecture or electronic design automation.

  • Design an oral presentation on a technical subject as demonstrated by presenting an analysis of a classic paper on hardware architecture or electronic design automation.

  • Create an opinion on a technical subject using appropriate sources as demonstrated by researching an analysis of a classic paper on hardware architecture on electronic design automation.

Course-Level Learning Outcomes, Fall 2026.

By the end of this course, students will be able to:

Engaged Learning

Students can expect the Engaged Learning element of this course to connect GPU programming skills to authentic computational problems through hands-on, collaborative work. Engaged Learning (5% of the course grade) is delivered through reflection posts, discussion-board activities, and out-of-class exercises, and culminates in the team Capstone project, in which students scope a real-world problem, design and implement a GPU-accelerated solution as a Colab notebook, profile it, and write an analysis of the results.

Methods of Evaluation

All individual work is completed in class under time constraints. There are no take-home assignments. Only the Capstone has a take-home component, completed as a team.

  • Quizzes (6) - Short Blackboard multiple-choice quizzes (15 min, auto-graded) taken at the start of a session. They check the conceptual building blocks - architecture, execution model, memory behavior - that the hands-on work depends on.

  • Labs (12) - Guided Colab notebooks worked through during the full Friday lab session. Graded on completion. Each lab introduces a skill you then practice without assistance in the paired checkpoint.

  • Checkpoints (12) - Short (20 min), individually-seeded, auto-graded fill-in-the-blank Colab exercises done at the end of the paired lab session. You submit a checksum to Blackboard.

  • Midterm Exam and Final Exam - Auto-graded Colab notebooks taken under Lockdown Browser. The Midterm covers Modules 0–3; the Final is comprehensive.

  • Capstone - A team GPU-acceleration project: scope a real-world problem, build the data pipeline and kernel or library solution, profile it, and write an analysis. Partly in class, partly take-home; graded on output and analysis.

  • Engaged Learning - Reflection posts, discussion-board activity, and out-of-class activities (see the Engaged Learning section above).

Late Work and Missed Assignment Policy

Assignments are due at 11:59 PM Eastern Time (UTC – 4) on the posted due date, with a one-hour grace period. Submissions received after that time will be subject to a late penalty of 10% of the maximum possible points per additional day past the deadline. The minimum grade on any assignment is zero; late penalties will not reduce a score below this.

Because the penalty accumulates continuously, assignments submitted several days late will earn little or no credit. Please plan accordingly and submit on time.

This policy is designed to ensure fairness and to allow me to return graded work to the class within 10 days of the due date. General requests for deadline extension requests will not be entertained after the scores for the assessment item has been posted.
