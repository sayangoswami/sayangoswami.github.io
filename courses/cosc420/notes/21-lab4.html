Lab 4: Write Your Own MapReduce Job

Module 1: Concurrency

Published

September 4, 2026

Date: October 21 Duration: 50 minutes Points: 10 Competency: C3.2 — Design map and reduce functions (in code) for a given data processing problem

Background

You’ve learned the MapReduce paradigm conceptually — map, shuffle/sort, reduce. Today you write a real one: a Java Mapper and Reducer for the same “count emails per domain” problem, and run it on the classroom Hadoop cluster.

You’re running in Hadoop’s local (standalone) mode today — no HDFS upload, no YARN job submission. Today is about the Mapper/Reducer code itself; Lab 5 is where you run a job across the real distributed pieces.

Setup

  1. Open your browser and go to the terminal URL on the board (hadoop-terminal.sayangoswami.dev)
  2. Log in with your course username and password
  3. You’re now in a real shell on the classroom Hadoop container, as yourself

Terminal basics — new to the command line? Read this first.

  • Copy: select text with the mouse — it’s copied automatically (you’ll see a ✂ flash). Don’t press Ctrl+Shift+C: in Chrome that opens the developer tools instead.
  • Paste: Ctrl+Shift+V, or right-click → Paste (Mac: Cmd+V).
  • Create or edit a file: nano FILENAME opens it in a simple editor (creating it if it doesn’t exist). Type or paste, then Ctrl+O, Enter to save and Ctrl+X to exit. The shortcuts are listed along the bottom of the nano screen (^ means Ctrl).
  • Look around: pwd shows where you are, ls lists files, mkdir creates a directory, cd DIR moves into a directory, cd .. goes back up, cat FILE prints a file.
  • Tilde (~) is a shortcut for your home directory.
  • Stuck? Ctrl+C cancels whatever is running and gives you the prompt back. Up-arrow recalls your previous command.
  • Your files here are temporary — they can be wiped when the server restarts. Keep a copy of anything you write (e.g. paste it into your Blackboard submission before you leave).

Task 1 — The Mapper (10 min)

Create EmailDomainCount.java with nano EmailDomainCount.java. This single file holds the Mapper, Reducer, and the driver (main) that wires them together — a full MapReduce job is always at least these three pieces.

import java.io.IOException;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class EmailDomainCount {

    public static class DomainMapper extends Mapper<Object, Text, Text, IntWritable> {
        private final static IntWritable one = new IntWritable(1);
        private Text domain = new Text();

        public void map(Object key, Text value, Context context)
                throws IOException, InterruptedException {
            String email = value.toString().trim();
            if (email.isEmpty()) return;

            // YOUR CODE HERE — extract everything after '@' as the domain,
            // set it into `domain`, and emit (domain, one).
            context.write(domain, one);
        }
    }

    public static class SumReducer extends Reducer<Text, IntWritable, Text, IntWritable> {
        public void reduce(Text key, Iterable<IntWritable> values, Context context)
                throws IOException, InterruptedException {
            // YOUR CODE HERE — sum the values for this key and emit (key, total).
        }
    }

    public static void main(String[] args) throws Exception {
        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "email domain count");
        job.setJarByClass(EmailDomainCount.class);
        job.setMapperClass(DomainMapper.class);
        job.setReducerClass(SumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

Fill in the map() method: extract the domain from the email address and emit (domain, 1).

Task 2 — The Reducer (10 min)

Fill in reduce(): sum the IntWritable values for a key and emit (key, total).

Question: The reducer receives Iterable<IntWritable> values — a whole list, not one value. Why? What phase is responsible for grouping all the values for a given key together before the reducer ever runs?

Task 3 — Compile and Run (20 min)

Create a small input file — the same 8 emails from the paper exercise, if you’ve done EL2:

cat > input.txt << 'EOF'
alice@gmail.com
bob@yahoo.com
carol@company.com
dave@gmail.com
eve@gmail.com
frank@yahoo.com
grace@company.com
henry@gmail.com
EOF

Compile against Hadoop’s own classpath, and package into a jar:

mkdir -p classes
javac -classpath $(hadoop classpath) -d classes EmailDomainCount.java
jar -cvf EmailDomainCount.jar -C classes .

Run it in local mode — the two -D flags below are what make this run as a single local process instead of submitting to the cluster, which is why no HDFS path or upload is needed today:

hadoop jar EmailDomainCount.jar EmailDomainCount \
  -D mapreduce.framework.name=local -D fs.defaultFS=file:/// \
  input.txt output

cat output/part-r-00000

If you need to re-run, delete the output directory first (rm -rf output) — same refuse-to-overwrite behavior you’ll see again in Lab 5.

Questions

  2. This job ran in local mode — one process, no cluster involved. What would need to change (conceptually — you don’t need to know the exact commands yet) to run this same jar against HDFS input, distributed across the real cluster instead?
