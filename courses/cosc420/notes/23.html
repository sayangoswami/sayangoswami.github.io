Variables, Types, and type()

count = 42          # int
price = 3.14        # float
name = "Alice"      # str
ok = True           # bool
scores = [90, 85]   # list
ages = {"Al": 30}   # dict

print(type(price))  # <class 'float'>
  • No type declarations. The value has a type, and the variable just points at it.
  • type(x) tells you what type a value is. It prints as <class 'float'>, not just float.
  • Watch the Java habits: 7 / 2 is 3.5 in Python (true division). Use 7 // 2 for 3.

Timing: 4 min. Quiz 4 Q3 asks for the exact output of print(type(3.14)) — point at the <class 'float'> form explicitly. Q10 asks which of int, str, list, char are real Python types — say explicitly that Python has no char type: 'a' is just a 1-character str.

= vs. ==, and Indentation Is Syntax

status = 200             # = assigns
if status == 200:        # == compares
    print("OK")          # indented: inside the if
    print("still OK")
print("always runs")     # not indented: outside the if

Output:

OK
still OK
always runs
  • = assigns; == compares. Writing if status = 200: is a syntax error in Python.
  • There are no braces. Indentation defines the block, and it’s required, not a style choice. Mixing up indentation changes what your program does, or stops it from running.
  • Every block-opening line (if, for, while, def) ends with a colon :.

Timing: 4 min. Quiz 4 Q2 (indentation is required) and Q6 (= vs. ==) come from this slide. Live demo: delete the indent on line 3 and run it, then indent line 5 and run it again.

Strings: Indexing, Slicing, split()

word = "python"
word[0]        # 'p'  — zero-indexed, like Java
word[2]        # 't'
word[-1]       # 'n'  — negative indexes count from the end
word[0:3]      # 'pyt' — slice: start up to (not including) end

line = "GET /index.html 200"
parts = line.split(" ")   # ['GET', '/index.html', '200']
code = int(parts[2])      # 200, now an int

Timing: 4 min. Quiz 4 Q7 asks for "python"[2]. split() + int() is exactly how Lab 6 and later MapReduce-style code parse a line, which is what EL1 Exercise 2 did with log lines.

Lists, len(), and range()

nums = [10, 20, 30, 40, 50]
len(nums)         # 5
nums.append(60)   # add to the end
nums[1]           # 20

for n in nums:    # loop over the items directly — no index needed
    print(n)      # 10, 20, 30, 40, 50, 60 (one per line)

for i in range(3):   # 0, 1, 2   (starts at 0, stops BEFORE 3)
    print(i)
  • len(x) works on lists, strings, dicts: anything with a size.
  • range(n) gives 0, 1, ..., n-1 — it stops before n. range(2, 5) gives 2, 3, 4.

Timing: 4 min. Quiz 4 Q1 (len of a 5-item list) and Q5 (range(3) prints 0 1 2) come from this slide. Stress “stops before n” — 1 2 3 and 0 1 2 3 are the wrong answers.

Dictionaries

person = {"name": "Alice", "age": 30}   # curly braces, key: value
person["name"]          # 'Alice'
person["email"] = "a@x.com"             # add a key

counts = {}
for word in ["a", "b", "a"]:
    counts[word] = counts.get(word, 0) + 1
# counts == {'a': 2, 'b': 1}

for key, value in person.items():
    print(key, value)   # name Alice / age 30 / email a@x.com
  • Python’s HashMap: keys map to values. .get(key, default) avoids a crash (KeyError) on a missing key.
  • A dict looks exactly like a JSON object — that’s why REST APIs (Module 2), MongoDB documents (Module 5) and Flask’s jsonify (Module 6) all feel natural in Python.

Timing: 4 min. Quiz 4 Q4 asks which syntax creates a dict with keys "name" and "age" — the example on this slide is that answer. The counts.get(...) loop is the word count pattern from Lab 6 Exercise 3 and Module 3’s reduce step.

Functions

def add(a, b):
    return a + b

add(3, 4)          # 7

def greet(name, greeting="Hello"):   # default argument
    return greeting + ", " + name

greet("Bob")                 # 'Hello, Bob'
greet("Bob", "Hi")           # 'Hi, Bob'
  • def, a name, parameters, a colon, then an indented body. No return type.
  • A function with no return returns None (Python’s null).

Pause & Discuss: Predict the Output

Breather — think on your own (2 min), then we discuss

data = {"alice": [90, 80], "bob": [70]}
for name in data:
    total = 0
    for s in data[name]:
        total = total + s
    print(name, total / len(data[name]))
print(len(data))

What does each print line output? What changes if the second print is indented one level?

Timing: 4 min (≈2 min silent thinking, ≈2 min discussion). Answers are on the next sub-slide so students reviewing later have them; reveal after the discussion.

Answer

alice 85.0
bob 70.0
2
  • 85.0, not 85: / always gives a float.
  • len(data) is the number of keys (2), not the number of scores (3).
  • Indenting print(len(data)) one level puts it inside the outer for, so it prints 2 twice, once after each student. Same code, different program: indentation is syntax.

List Comprehensions, lambda, and sorted

nums = [1, 2, 3, 4, 5]
squares = [n * n for n in nums]              # [1, 4, 9, 16, 25]
evens   = [n for n in nums if n % 2 == 0]    # [2, 4]

A list comprehension builds a new list in one line: [expression for item in list if condition].

It’s shorthand for a loop you already know how to write:

evens = []
for n in nums:
    if n % 2 == 0:
        evens.append(n)

Timing: 5 min across this slide and the next. Write the comprehension as the equivalent for loop first (the second block), then collapse it. Lab 6 Exercise 1 and Exercise 3 both use these directly.

pairs = [("bob", 70), ("alice", 85), ("carol", 92)]
sorted(pairs, key=lambda p: p[1], reverse=True)
# [('carol', 92), ('alice', 85), ('bob', 70)]
  • A lambda is a tiny unnamed function. lambda p: p[1] means “given p, return p[1].”
  • sorted(..., key=...) sorts by whatever the key function returns — here, the score. reverse=True puts the biggest first.
  • You’ll see both in Lab 6 and all over Python code. In PySpark, though, you’ll use Spark’s own filter/select instead of comprehensions (Session 2 shows why).

Reading a File

f = open("ratings.csv", "r")     # "r" = read mode
for line in f:
    print(line.strip())
f.close()

# The idiomatic version: the file closes itself when the block ends
with open("ratings.csv", "r") as f:
    header = f.readline()            # skip the header row
    for line in f:
        user, movie, rating, ts = line.strip().split(",")
  • open(path, "r") to read, "w" to write (overwrites the file).
  • with open(...) as f: is preferred: no forgotten close().
  • The unpacking needs one name per field: ratings.csv has four columns (userId,movieId,rating,timestamp), so three names would crash with a ValueError.

Timing: 4 min. Quiz 4 Q9 asks which call opens data.txt for reading — open("data.txt", "r"). EL2 Exercise 1 is load_lines(path, skip_header=True), built from exactly this pattern; the tuple unpacking on the last line is EL2 Exercise 2.
