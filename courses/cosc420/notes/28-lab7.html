Lab 7: PySpark Transformations

Background

Today you write your first real PySpark jobs in Colab, using the same local Spark session you started in Lab 6. You will explore the fundamental distinction between transformations (which define what to compute) and actions (which actually trigger the computation). This lazy evaluation model is what makes Spark efficient at scale. At the end, you connect the same notebook to the classroom Hadoop/Spark cluster and run the same code there, unchanged.

Setup

  1. Open colab.research.google.com and create a new notebook, Lab7_PySpark

  2. Make the first two cells the same as Lab 6’s Part 2 setup, and run them:

    !pip install -q "pyspark==4.0.0"
    from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .master("local[*]") \
    .appName("Lab7") \
    .getOrCreate()

Tasks 1–3 run locally in Colab, as ordinary cells. Task 4 is where the classroom cluster comes in.

Task 1 — Create a DataFrame and Explore It (10 min)

Run each cell below one at a time and observe what happens.

Cell 1 — Create data:

data = [
    ("Alice",   "Engineering", 95000),
    ("Bob",     "Marketing",   62000),
    ("Carol",   "Engineering", 78000),
    ("Dave",    "Marketing",   71000),
    ("Eve",     "Engineering", 110000),
    ("Frank",   "HR",          58000),
    ("Grace",   "HR",          61000),
    ("Henry",   "Marketing",   83000),
]
columns = ["name", "department", "salary"]

df = spark.createDataFrame(data, columns)

Cell 2 — Inspect:

df.printSchema()
df.show()

Questions:

  1. What does printSchema() tell you? What are the data types Spark inferred?
  2. What does show() do? Is this a transformation or an action? How do you know?

Task 2 — Transformations vs. Actions (15 min)

Run each line below in separate cells. Before running each one, predict whether it will trigger computation or just define a plan.

# Cell A — transformation
filtered = df.filter(df["salary"] > 70000)

# Cell B — transformation
selected = filtered.select("name", "salary")

# Cell C — action
selected.show()

# Cell D — action
count = selected.count()
print(f"Employees earning > $70,000: {count}")

# Cell E — transformation (just building a plan)
sorted_df = df.orderBy("salary", ascending=False)

# Cell F — action
sorted_df.show()

Questions:

  1. After running Cell A and Cell B, did anything print to the screen? What does this tell you about how Spark handles transformations?
  2. What is a DAG (Directed Acyclic Graph) in Spark? When does Spark build it and when does it execute it?
  3. Between Cells C and F, which one do you think took longer to run? Why?

Task 3 — Chain Transformations and Read the Execution Plan (15 min)

Build a query from four transformations — filter, add a column, select, sort — then trigger it once with a single action. Assign each step to a new variable (DataFrames are immutable; Session 1).

# Step 1 — keep only employees earning more than 60,000
high_earners = df.filter(df["salary"] > 60000)

# Step 2 — add a computed column: a 10% bonus
with_bonus = high_earners.withColumn("bonus", high_earners["salary"] * 0.10)

# Step 3 — select the columns we want to see
report = with_bonus.select("name", "department", "salary", "bonus")

# Step 4 — sort by bonus, highest first
ranked = report.orderBy("bonus", ascending=False)

# Nothing above has run yet. THIS triggers the whole chain:
ranked.show()

Expected output:

+-----+------------+------+-------+
| name|  department|salary|  bonus|
+-----+------------+------+-------+
|  Eve| Engineering|110000|11000.0|
|Alice| Engineering| 95000| 9500.0|
|Henry|   Marketing| 83000| 8300.0|
|Carol| Engineering| 78000| 7800.0|
| Dave|   Marketing| 71000| 7100.0|
|  Bob|   Marketing| 62000| 6200.0|
|Grace|          HR| 61000| 6100.0|
+-----+------------+------+-------+

Now replace ranked.show() with ranked.explain() and run it again.

Questions:

  1. Before you called .show(), you ran the four transformation steps (Steps 1–4). Did any of them print rows or otherwise touch the data? What does that confirm about lazy evaluation?
  2. Look at the .explain() output. Which operations does Spark list (e.g. Filter, Project, Sort)? You wrote five steps (filter, withColumn, select, orderBy, show) — does the plan have five matching stages, or fewer? (Hint: count how many Project nodes appear versus the two column operations you wrote.) What does that tell you about the relationship between the code you write and the work Spark actually does?

Bonus Task 4 — Same Code, Real Cluster (10 min)

So far everything has run on the Colab VM. Now connect this notebook to the classroom cluster with sparkmagic, a notebook extension that sends a cell’s code over HTTPS to the cluster (via Apache Livy) and brings the printed output back. It adds a %%spark cell magic: a cell that starts with %%spark runs on the cluster; every other cell keeps running in Colab.

Add these three cells and run them in order. Each must be its own cell, since %%spark config has to be the first line of its cell.

!pip install -q sparkmagic
%load_ext sparkmagic.magics
%%spark config
{"driverMemory": "512m", "executorMemory": "512m", "numExecutors": 1}
from getpass import getpass
username = "<your-linux-username>"
password = getpass("Classroom cluster password: ")
%spark add -s classroom -l python -u https://hadoop-spark.sayangoswami.dev -a {username} -p {password} -t Basic_Access

Use the same username and password as the classroom terminal (Lab 4/5). The add cell takes a minute or more while the cluster starts a Spark session for you (longer when the whole class connects at once, so start it, then keep going on your Task 1–3 answers). That session gets its own spark object. You don’t create this one. If your password has spaces or quote characters in it, the add line can’t parse it, so ask the instructor to reset it.

Colab forgets this connection when its runtime resets, just like the local session. Keep these three cells near the top of every notebook that uses the cluster (Lab 8 and the capstone) and re-run them each time you come back.

Now run the following, each in its own cell with %%spark as the first line:

%%spark
print(spark.sparkContext.master)
%%spark
# paste Task 1's Cell 1 here (the data list, columns, and createDataFrame)
%%spark
# paste the Task 3 chain here, ending with:
ranked.show()
ranked.explain()

Questions:

  1. What does spark.sparkContext.master print on the cluster? How does that compare with what it printed in Lab 6?
  2. You had to paste Task 1’s Cell 1 again before the Task 3 chain would run, even though df already exists in your notebook. Why?
  3. Compare this .explain() output with the one from Task 3. Is the plan the same or different? What does that tell you about where your code runs vs. what your code means?
