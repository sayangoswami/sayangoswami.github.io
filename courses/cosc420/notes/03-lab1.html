Lab 1: The Race Condition Game

Date: September 4
Duration: 50 minutes
Points: 10
Competency: C1.1 — Identify race conditions in concurrent Java code

Background

A race condition occurs when two threads read and modify a shared variable at the same time, producing unpredictable results. Today you will watch a race condition happen in a real Java program, then answer questions about what you observed.

This is a guided demo lab. The instructor will run the main demonstrations. Your job is to run the programs yourself, record what you see, and answer the questions below.

Setup

Create a new file in the IDE of your choice. You will be given the code — you do not need to write it from scratch today.

Part 1 — Observe a Race Condition (20 min)

Copy and run the following Java program three times. Record the output each time.

public class RaceCondition {
    static int counter = 0;

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) counter++;
        });
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 10000; i++) counter++;
        });
        t1.start();
        t2.start();
        t1.join();
        t2.join();
        System.out.println("Final counter: " + counter);
    }
}

Questions — answer in a text file or on paper:

  1. What value did you expect the counter to be? What values did you actually get across your three runs?
  2. Why does the counter not always reach the expected value?
  3. Two threads are both doing counter++. Explain in your own words what three low-level steps counter++ actually involves and why that makes it unsafe.

Part 2 — Fix It with synchronized (20 min)

Modify the program so that the counter always reaches the correct value. Add the synchronized keyword to a helper method and call it instead of counter++ directly.

// Replace the counter++ lines with a call to this method:
static synchronized void increment() {
    counter++;
}

Run the fixed version three times. Confirm the output is always correct.

Questions:

  1. What value does the counter reach now on every run?
  2. In one sentence: what does synchronized prevent?
  3. Do you notice any difference in how long the program takes to run? Why might synchronized slow things down?
