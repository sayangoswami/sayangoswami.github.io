Lab 9: MongoDB Atlas CRUD

Date: November 23 Duration: 50 minutes
Points: 10
Competency: C5.3 — Perform CRUD operations on a MongoDB collection

Background

MongoDB stores data as documents (JSON-like objects) rather than rows in a table. Today you will connect to MongoDB Atlas, create a collection, and practice all four CRUD operations: Create, Read, Update, and Delete.

You will use the MongoDB Atlas web shell (no installation required) and Python in a Colab notebook.

Setup

Create your Atlas account and cluster (first time only — you’ll reuse this same account for the capstone): 1. Go to cloud.mongodb.com and sign up — free, email only, no credit card 2. Create a free (M0) cluster — takes a couple of minutes to provision 3. Database Access → add a database user (username + password). Save these somewhere safe — a password manager, not a shared doc or anything you’ll upload — you’ll need them again for the capstone 4. Network Access → add an IP entry. If you work from more than one network (classroom, home), “Allow access from anywhere” (0.0.0.0/0) is acceptable for this class’s low-stakes free-tier use 5. Once the cluster shows Active: Connect → Drivers → choose Python → copy the mongodb+srv://... connection string. That’s your MONGO_URI for the rest of this lab.

Atlas web shell: 1. Click your cluster → Collections → Browse Collections 2. Create a new database: click + Create Database, name it lab9, collection employees

Python (Colab):

!pip install pymongo
from pymongo import MongoClient

MONGO_URI = "mongodb+srv://<user>:<password>@<cluster>.mongodb.net/"

Task 5 — Schema Flexibility (5 min)

One of MongoDB’s key differences from relational databases is that documents in the same collection do not need to have the same fields. Insert these two documents into a new collection called products and then query all documents:

products = db["products"]
products.insert_many([
    {"name": "Laptop",  "price": 999.99, "brand": "Dell", "warranty_years": 2},
    {"name": "Headset", "price": 79.99,  "color": "black", "wireless": True},

for doc in products.find({}, {"_id": 0}):

Question: Could you store these two documents in the same SQL table without changing the schema? What would you have to do in SQL that MongoDB does not require?
