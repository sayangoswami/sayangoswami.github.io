Date: October 23

Points: 10
Competency: Enabling lab — Python fluency for PySpark (EL1/EL3 prerequisite)

Background

PySpark is Python. Before you can write Spark jobs, you need to be comfortable with the Python features that PySpark uses constantly: lists, dictionaries, functions, and list comprehensions. Today you practice these in Google Colab, then start your first Spark session right inside the same Colab notebook. Everything in this course’s PySpark work (Labs 7 and 8 and the capstone) happens in Colab; starting in Lab 7, you’ll also connect that notebook to the classroom Hadoop/Spark cluster.

Part 2 — Your First Spark Session, in Colab (20 min)

PySpark is just a Python library, so the quickest way to meet Spark is to run it right inside your Colab notebook. Spark’s local[*] mode runs the whole engine on the Colab VM (the driver and the workers become threads in one process) instead of spreading work across a cluster. You write exactly the same DataFrame code either way, which is why we start here: Lab 7 builds your first real PySpark job in this setup, then runs the same code unchanged on the classroom cluster.

Steps:

  1. In a new cell in the same Colab notebook, install PySpark at the same version as the classroom cluster (Spark 3.5.x):

    !pip install -q "pyspark==4.0.0"

  2. Start a local Spark session:

    from pyspark.sql import SparkSession

spark = SparkSession.builder \
    .master("local[*]") \
    .appName("Lab6") \
    .getOrCreate()

  3. In the next cell, run:

    print(spark.version)
print(spark.sparkContext.master)
print(spark.sparkContext.defaultParallelism)
spark.range(5).show()

  4. Take a screenshot of the output

Call it spark, not spark_local or anything else. On the classroom cluster (Lab 7 onward), the session is created for you and it’s always named spark. Using the same name here means every line you write locally runs unchanged on the cluster.

Important: Colab’s runtime resets between sessions, and the installed PySpark and your spark session disappear with it. Re-run the Step 1 and Step 2 cells at the top of the notebook each time you come back. Get in the habit of keeping them as the first two cells.

Questions:

  1. What version of Spark are you running?
  2. What does spark.range(5).show() print? What type of object is the result of spark.range(5)?
  3. What do spark.sparkContext.master and spark.sparkContext.defaultParallelism print? Based on that, where did the computation actually happen, and on how many machines?
