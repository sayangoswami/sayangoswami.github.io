Course Description

Official catalog description:

This course studies the methods for using several computers connected by a network to solve a single problem. Topics include networking services, middleware (CORBA, DCOM, SOAP, RMI and RPC), two- and three-tier client-server systems, algorithms for parallel computing, performance evaluation and hardware architectures (clusters, grids, surfaces).

Course focus, Fall 2026:

COSC420 is a hands-on introduction to the ideas and tools behind modern distributed and parallel computing. The course moves through six modules: (1) concurrency and thread safety in Java; (2) distributed systems concepts, including partial failure and the CAP theorem; (3) big data and the MapReduce model on Apache Hadoop/HDFS; (4) large-scale data analysis with Apache Spark and PySpark; (5) distributed storage and NoSQL databases with MongoDB; and (6) cloud computing service models and microservices, including building a REST API with Python Flask. The term culminates in a capstone in which pairs of students build an end-to-end data pipeline that moves a real dataset through HDFS, Spark, MongoDB, and a Flask dashboard. Work is done on the student’s own laptop against an instructor-hosted Hadoop/Spark cluster; no paid services are required.

Course Learning Outcomes

Official catalog outcomes:

Upon completion of the course, students will be able to:

  • Explain networking for distributed computing as demonstrated by short answers during examination.
  • Execute performance evaluation of a parallel and distributed system.
  • Explain middleware for distributed and parallel computing as demonstrated by short answers during examination.
  • Model hardware architectures for distributed and parallel computing as demonstrated by short answers during examination.
  • Implement common parallel and distributed computing algorithms as demonstrated by development of programs.
  • Construct parallel and or distributed computing solution as demonstrated by development of a significant project.

Course-Level Learning Outcomes, Fall 2026.

Upon completion of the course, students will be able to:

  1. Write thread-safe Java programs using synchronization primitives and thread-pool mechanisms.
  2. Analyze distributed system design decisions by applying the CAP theorem to evaluate consistency and availability trade-offs.
  3. Explain the MapReduce execution model and use Apache Hadoop to run distributed data-processing jobs on HDFS.
  4. Use PySpark to load, transform, and analyze large datasets with the DataFrame API.
  5. Compare relational and NoSQL storage approaches and select an appropriate database design for a given scenario.
  6. Describe cloud computing service models and the microservices architectural pattern, and build a simple REST API using Python Flask.
  7. Design and implement an end-to-end distributed data pipeline integrating HDFS, Apache Spark, a NoSQL database, and a REST API.

Engaged Learning

Students can expect the Engaged Learning element of this course to connect the technical material to how distributed systems are actually built and operated in industry, and to build the prerequisite Python skills needed for the Spark modules. Engaged Learning is delivered as six completion-graded activities (5% of the course grade) done outside class: reading and reflecting on an industry case study, two self-paced Python self-learning modules, watching a Spark tech talk, reading a real cloud outage post-mortem and explaining the failure in distributed-systems terms, and a pencil-and-paper MapReduce tracing exercise verified with a short Python script.

Methods of Evaluation

Your course grade is based on checkpoints, labs, quizzes, a midterm exam, a final exam, a capstone project, and engaged-learning activities. Most components emphasize hands-on work with real tools.

  • Checkpoints (8) - Short, timed, individual exercises in the last 15–20 min of a lecture session, testing understanding of what was just taught that day. Graded on output: correct = full credit, genuine attempt = partial credit, not attempted = 0.
  • Labs (10) - Full 50-minute hands-on Friday sessions in which you build and run something end-to-end using real tools (Java threading, REST APIs, Hadoop/HDFS, PySpark, MongoDB Atlas, Flask). Graded on completion and correct output.
  • Quizzes (8) - Blackboard multiple-choice and true/false, auto-graded, taken during the last 10–15 min of a Friday lab session. They cover the building-block concepts of each module.
  • Midterm Exam - In-class Blackboard exam (MC + short answer) covering Modules 1–3.
  • Final Exam - Blackboard exam (MC + short answer) during finals week. Comprehensive, but weighted toward Modules 4–6, which are not on the midterm.
  • Capstone - A pair project with a live demo: an end-to-end data pipeline (HDFS → PySpark → MongoDB → Flask dashboard). Graded against a checklist rubric.
  • Engaged Learning (6) - Completion-graded reflection and self-study activities done outside class (see the Engaged Learning section above).

Course Attendance Policy

Attendance is not mandatory, and thus absence from class is not penalized directly, but you will lose out in other ways. Class attendance is the #1 indicator of academic success. OS3 emphatically encourages all students to Go To Class! Class attendance is important for numerous reasons:

  • Students tend to remember info more when they attend class.
  • Your presence in class shows your instructor that you care about the course and it is important to you. If your grade is borderline at the end of the semester, the instructor may give you the benefit of the doubt because you regularly attended class.
  • You/your families are paying to be in class. In-state residents who miss a class are wasting over $56 per class. Out-of-state students who miss a class are throwing away $110 per class!
  • Your instructor will likely explain material differently/better than you can learn it yourself, and can answer questions more directly.
  • Going to class helps you build community and relationships with peers and your instructors.
  • By not going to class, you may miss a pop quiz, participation points, extra credit opportunities, important info, or in-class assignments that can impact your grade.

To the Point establishes the baseline attendance policy for SMCM courses. 

Please note: Per the SMCM policy, there is no distinction between “excused” or “unexcused” absences; an absence is an absence.

Late Work and Missed Assignment Policy

Assignments are due at 11:59 PM Eastern Time (UTC – 4) on the posted due date, with a one-hour grace period. Submissions received after that time will be subject to a late penalty of 10% of the maximum possible points per additional day past the deadline. The minimum grade on any assignment is zero; late penalties will not reduce a score below this.

Because the penalty accumulates continuously, assignments submitted several days late will earn little or no credit. Please plan accordingly and submit on time.

This policy is designed to ensure fairness and to allow me to return graded work to the class within 10 days of the due date. General requests for deadline extension requests will not be entertained after the scores for the assessment item has been posted.

Use of Generative Artificial Intelligence in the Classroom 

Generative artificial intelligence (AI) (tools such as ChatGPT, Gemini, Copilot) is a fast-developing tool that greatly impacts the learning process. As with many things, there are times when using these tools is appropriate and when it is not.  For this course, I encourage you to use the generative AI tools at your disposal for learning and practice, but not for checkpoints and quizzes. However it is your responsibility to properly evaluate the information created through generative AI. We will discuss how to do this in class, and you should contact me with any questions that you may have if you encounter a situation where it is unclear how to do use AI. Failure to disclose the use generative AI tools in assignments and quizzes may be considered plagiarism and will be handled via the SMCM Academic Misconduct policies.
