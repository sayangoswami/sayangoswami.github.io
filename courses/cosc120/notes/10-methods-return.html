Return Values and Scope

COSC120: Introduction to Computer Science I

Learning Outcomes

By the end of this lecture, you’ll be able to:

  • Define methods that compute and return a value using the return statement
  • Store and use a method’s return value in a variable, expression, or condition
  • Write methods with multiple return statements in different branches
  • Explain what scope means and identify the scope of a local variable
  • Trace a method call with a return value and show what the caller receives

The Limitation of void

Open by revisiting what void means in the context of the last two lectures. Void methods DO things — they print, they perform actions. But they give nothing back. What if you need the result of a computation to use somewhere else? Show the limitation concretely on the second sub-slide: a void method can print the doubled number, but you can’t store that printed value in a variable or use it in a condition. You have no way to get the answer OUT of the method. This sets up the natural question: what if the method could hand you the result?

In the last two lectures, all methods started with void:

void printBanner() { ... }
void greet(String name) { ... }
void printScore(String player, int score) { ... }

void means the method does something — but gives nothing back.

That works when you just want to print or perform an action.

But what if you need to use the result of a computation?

void doubleIt(int n) {
    IO.println(n * 2);   // prints the result — but where does it go?
}

void main() {
    doubleIt(5);          // prints 10 — fine
    int x = doubleIt(5);  // ✗ won't compile: doubleIt gives nothing back
}

The result disappears the moment it is printed. You cannot store it, use it in a calculation, or pass it to another method.

There is a better way.

Functions in Mathematics

Students have been writing functions since middle school. This slide is the central hook for the lecture — the direct bridge between math and programming. Go slowly and make the parallel explicit. f(x) = x² is a function: it takes a number, squares it, and produces a result. g(x, y) = x + y takes two numbers, adds them, and produces a result. The “produces a result” part is the key — the function doesn’t just DO something, it GIVES YOU BACK A VALUE. The figure on the second sub-slide shows the result 9 flowing out and being reused three ways.

You have been working with functions in math for years:

\[f(x) = x^2 \qquad g(x, y) = x + y \qquad h(x) = 2x + 1\]

Each function:

  • Takes input (the values in the parentheses)
  • Computes something
  • Produces a result — a value you can use anywhere

When you write \(f(3)\), you get back \(9\) — and you can keep using that \(9\):

Java methods work exactly the same way. The only difference is that you also have to tell Java what type of value the method will produce.

Methods as Functions

Now the translation from math to Java, one piece at a time. The return type replaces void — it goes in the same position, but instead of saying “produces nothing,” it says “produces a value of this type.” The return keyword sends the value back to whoever called the method. Walk through the parallel carefully: f(x) = x² becomes int square(int x) { return x * x; }. The math equals sign becomes the return statement. The figure on the second sub-slide lines up each math symbol with its Java counterpart.

Translating a math function into Java:

Math Java
\(f(x) = x^2\) int square(int x) { return x * x; }
\(g(x, y) = x + y\) int add(int x, int y) { return x + y; }
\(h(x) = 2x + 1\) int linear(int x) { return 2 * x + 1; }

Two things changed from void methods:

  1. void is replaced by the return type — the type of value the method produces (int, double, String, boolean, …)
  2. return sends the value back — it plays the role of the = sign in the math function

The method computes a value and hands it back to whoever called it.

The return Statement

The mechanics of return: it sends a value back to the caller and immediately stops the method. Nothing after a return statement in the same branch will run. This is important for multiple-return methods later. Show the syntax first, then show that the method stops at return with a concrete example. The “method stops here” behavior surprises students — they expect the method to keep running. Java goes further: if a line can never run because it comes right after a return, the program won’t compile (“unreachable statement”). Connect to math: when f(3) = 9, you don’t ask “and then what does f do?” — the function just produces the value and it’s over.

The return statement does two things:

  1. Sends a value back to whoever called the method
  2. Stops the method immediately — no further lines in that branch run
int square(int x) {
    return x * x;     // sends back the result AND stops the method
    IO.println("Hi"); // ✗ can never run — Java refuses to compile: "unreachable statement"
}

The syntax:

return expression;

The expression can be any value of the right type — a literal, a variable, a calculation:

int twice(int n)       { return n * 2; }
double half(int n)     { return n / 2.0; }
String shout(String s) { return s.toUpperCase(); }
boolean isEven(int n)  { return n % 2 == 0; }

Warning

The type of the expression after return must match the return type declared before the method name. int square(int x) { return 3.14; } is an error — you declared int but tried to return a double.

Using the Return Value

The return value comes back to the call site — and you can do three things with it: store it in a variable, use it directly in an expression, or use it in a condition. Show all three. The most common beginner mistake is ignoring the return value entirely — calling square(5) without doing anything with the result is legal but pointless. Also: the return value can be passed as an argument to another method, which is the basis of expression chaining.

When a method returns a value, you can use that value in three ways:

1. Store it in a variable:

int result = square(5);        // result holds 25
String loud = shout("hello");  // loud holds "HELLO"

2. Use it directly in an expression:

IO.println(square(5) + 1);    // prints 26
IO.println(square(3) * 2);    // prints 18

3. Use it in a condition:

if (square(4) > 10) {
    IO.println("Big square!");   // 16 > 10, so this prints
}

if (isEven(10)) {
    IO.println("Even number.");  // isEven(10) is true, so this prints
}

You can also pass a return value directly as an argument to another method:

IO.println(square(5));        // square(5) produces 25; println prints 25
IO.println(shout("hello"));   // shout produces "HELLO"; println prints it

Warning

Calling a method with a return value but doing nothing with the result is legal but almost always a mistake:

square(5);    // computes 25 and immediately discards it — probably a bug

Piecewise Functions and Multiple Returns

In math, some functions are defined differently for different inputs — piecewise functions. The absolute value is the classic example: f(x) = x if x ≥ 0, and f(x) = -x if x < 0. In Java, this maps naturally to if/else with a return in each branch. The key rule: every path through the method must reach a return statement. If some path reaches the end without a return, Java will refuse to compile. On the letterGrade sub-slide, trace letterGrade(87) aloud before revealing the walkthrough: it’s a nice reminder that return stops the method, so the remaining checks never run.

In math, a piecewise function produces different results depending on the input:

\[|x| = \begin{cases} x & \text{if } x \geq 0 \\ -x & \text{if } x < 0 \end{cases}\]

In Java, this maps directly to if/else with a return in each branch:

int abs(int x) {
    if (x >= 0) {
        return x;    // if x is non-negative, return x as-is
    } else {
        return -x;   // if x is negative, flip the sign
    }
}

Each branch reaches a return. The method ends as soon as one of them runs.

IO.println(abs(5));    // 5
IO.println(abs(-3));   // 3
IO.println(abs(0));    // 0

Another example — letter grade from a score:

String letterGrade(int score) {
    if (score >= 90) {
        return "A";
    } else if (score >= 80) {
        return "B";
    } else if (score >= 70) {
        return "C";
    } else if (score >= 60) {
        return "D";
    } else {
        return "F";
    }
}

letterGrade(87): is 87 ≥ 90? No. Is 87 ≥ 80? Yes → return "B". The method stops there — the remaining checks never run.

Warning

Every path through the method must reach a return. If Java can find a path that doesn’t, it will refuse to compile: “missing return statement.”

int square(int n) {
    return n * n;
}

Think of the call square(4) being replaced by its result — as if Java rewrote the line:

IO.println(square(3) + 1);

IO.println(9 + 1);

The method call is replaced by the value it returns, wherever it appears.

What Is Scope?

Scope is where a variable exists. This is the second main concept of the lecture and the natural follow-on from return values — because once you understand that variables can only be used inside their method, the question “how does the result get OUT?” is answered by: the return value. The scope concept is also the full treatment of the point briefly mentioned at the end of deck 09 (“Parameters Are Local”). Use the “bubble” analogy, drawn on the second sub-slide: each method is a bubble. Variables declared inside the bubble only exist inside the bubble. When the bubble pops (when the method ends), all variables inside disappear.

Scope is the region of code where a variable exists and can be used.

Every variable declared inside a method only exists inside that method:

int addOne(int n) {
    int result = n + 1;    // 'result' is born here
    return result;         // the VALUE of result escapes — the variable does not
}                          // 'result' ceases to exist here

void main() {
    int x = addOne(5);
    IO.println(result);    // ✗ won't compile: 'result' does not exist here
    IO.println(x);         // ✓ x holds 6 (the value that escaped)
}

The return value is the one thing that escapes the method’s scope. Everything else stays inside.

Local Variables

A local variable is any variable declared inside a method — parameters count too. All local variables are scoped to their method. This is not a limitation — it is a feature. It means methods are truly self-contained. Two different methods can use the same variable name (like “result” or “temp”) without any conflict, because each lives in its own bubble. Show the non-conflict example — students are sometimes surprised that the same name in two methods is legal and completely independent.

A local variable is a variable declared inside a method. Parameters are local variables too.

All local variables:

  • Are created when the method is called
  • Only exist inside that method
  • Cease to exist when the method ends
int timesTwo(int n) {
    int result = n * 2;   // 'result' is local to timesTwo
    return result;
}

int timesThree(int n) {
    int result = n * 3;   // also named 'result' — completely independent
    return result;
}

These two result variables are completely separate. They happen to share a name, but they live in different bubbles. Changing one has zero effect on the other.

Note

This independence is a feature, not a bug. Methods are self-contained units. You can write and test them without worrying about variable names clashing with other methods.

void vs. Return: Which to Use?

A simple decision rule that maps to the do/compute distinction. Methods that perform an action (print, modify, draw) are usually void. Methods that compute a value the caller needs to use have a return type. The math analogy is useful: in math you distinguish between “procedures” (algorithms that do a sequence of steps) and “functions” (mappings that produce a value). In Java, void = procedure, return type = function. The rule of thumb: if the caller needs to DO SOMETHING WITH the result, use a return type. If the caller just needs the method to ACT, use void.

Two kinds of methods. Two different jobs:

void With return type
Does what? Performs an action Computes a value
Gives back Nothing A value the caller can use
Math analogy Procedure Function
Example printBanner() square(int x)

Use void when the method’s job is to do something:

  • Print output
  • Draw something
  • Save something

Use a return type when the method’s job is to compute and hand back a value:

  • Calculate a result
  • Check a condition and answer yes/no
  • Transform a value (uppercase, round, format)

Tip

Ask yourself: “Does the caller need to use this result somewhere?” If yes → return type. If the method just acts and the caller moves on → void.

Common Mistakes

Four mistakes that show up constantly this week. The most dangerous is forgetting to return — Java catches this at compile time for non-void methods, but students are still confused by the error message. Ignoring the return value is legal but almost always wrong. Using a variable outside its scope produces a confusing error message because Java just says the variable doesn’t exist — students wonder where it went. For each one, show the code, ask students to identify the problem, then click to reveal it.

1. Forgetting to return in a non-void method

int square(int n) {
    int result = n * n;
}

Won’t compile: “missing return statement.” The method computes result but never hands it back. Fix: add return result;.

2. A path through the method that never reaches return

int abs(int x) {
    if (x >= 0) {
        return x;
    }
}

Won’t compile: what if x < 0? That path reaches the end with no return.

Fix: add else { return -x; } or return -x; after the if block.

3. Ignoring the return value

square(5);
int x = square(5);
  • square(5); — compiles, but computes 25 and immediately discards it
  • int x = square(5); — ✓ stores the result so you can use it

4. Using a local variable outside its method

int addOne(int n) {
    int result = n + 1;
    return result;
}

void main() {
    addOne(5);
    IO.println(result);
}

IO.println(result); won’t compile: result lived inside addOne and is gone. Store the return value in a variable in main instead: int result = addOne(5);.

Key Takeaways

A one-slide recap students can come back to when studying. There is no textbook, so this is the page they will revisit before the test. Read each line aloud and ask the class for an example of each.

  • A method’s return type (in place of void) says what kind of value it gives back: int square(int x).
  • return sends a value back to the caller and stops the method immediately.
  • The returned value replaces the call: you can store it, use it in an expression, or test it in a condition.
  • Calling a returning method and ignoring the result is legal but almost always a bug.
  • Every path through a non-void method must reach a return, or it won’t compile.
  • Scope is where a variable exists. Local variables (including parameters) exist only inside their method.
  • Use void when a method does something; use a return type when it computes a value.
