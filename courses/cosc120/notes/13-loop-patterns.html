Loop Patterns

COSC120: Introduction to Computer Science I

Learning Outcomes

By the end of this lecture, you’ll be able to:

  • Implement the accumulator pattern to compute a running total, product, or maximum
  • Implement the counter pattern to count values that satisfy a condition
  • Implement the sentinel pattern to loop until a special input value signals the end
  • Combine accumulator and counter patterns in a single loop
  • Identify which loop pattern applies to a given problem

What Is a Pattern?

A loop pattern is a reusable template: the same loop shape works for many different problems.

Think of it like a cookie cutter: the cutter doesn’t care what flavor of dough you use. You just press and cut.

Pattern What it does
Accumulator Builds up a value iteration by iteration
Counter Counts how many iterations satisfy a condition
Sentinel Runs until a special “stop” value appears

Frame this deck as building a toolkit. Students already know the mechanics from decks 11–12; now they’re learning to NAME the shapes. Naming patterns matters: it lets you talk about code, recognize problems faster, and write solutions without starting from scratch each time.

The Accumulator Pattern

Template:

type result = <identity>;    // initialize BEFORE the loop

for (...) {
    result = result <op> nextValue;    // update each iteration
}

// use result AFTER the loop

The starting value is the operation’s identity: the value that leaves anything unchanged.

Goal Identity Operation Why
Sum 0 + 0 + x is x
Product 1 * 1 * x is x
Concatenation "" + (String) "" + x is x

The “identity” value is the one that leaves the result unchanged: 0 + anything = anything; 1 * anything = anything; “” + anything = anything. Starting with the wrong identity gives a wrong answer (e.g., starting a product at 0 always gives 0).

Accumulator: Sum of Inputs

int sum = 0;

for (int i = 1; i <= 5; i++) {
    String input = IO.readln("Enter number " + i + ": ");
    int n = Integer.parseInt(input);
    sum = sum + n;
}

IO.println("Total: " + sum);

Sample run (user enters 3, 7, 1, 4, 2):

Enter number 1: 3
Enter number 2: 7
Enter number 3: 1
Enter number 4: 4
Enter number 5: 2
Total: 17

sum grows one input at a time: 0 → 3 → 10 → 11 → 15 → 17.

Walk through the sum example with the concrete run on the second sub-slide: the running sum is 0→3→10→11→15→17. The loop counter i is only used for the prompt and to stop after 5; the value being accumulated is n, not i — contrast with deck 12 where we summed i itself.

Accumulator: Concatenation

The same shape builds a String, starting from the empty string "":

String digits = "";

for (int i = 1; i <= 5; i++) {
    digits = digits + i;
}

IO.println(digits);

Output:

12345

Sum, product (Lecture 12’s 5!), and concatenation are the same loop: only the starting value and the operation change.

This shows the third row of the identity table. digits goes “” → “1” → “12” → “123” → “1234” → “12345”. Because digits is a String, + glues instead of adding. Ask: what if digits started as 0 (an int)? Then it would add: 15.

Accumulator: Maximum

Finding the largest value needs a different starting value:

String first = IO.readln("Enter number 1: ");
int max = Integer.parseInt(first);    // start with the first value

for (int i = 2; i <= 5; i++) {
    String input = IO.readln("Enter number " + i + ": ");
    int n = Integer.parseInt(input);
    if (n > max) {
        max = n;        // update only when a new champion is found
    }
}

IO.println("Maximum: " + max);

Sample run (user enters 4, 9, 2, 12, 7):

Enter number 1: 4
Enter number 2: 9
Enter number 3: 2
Enter number 4: 12
Enter number 5: 7
Maximum: 12

Note

For maximum there is no identity value: starting at 0 would give the wrong answer if every input is negative. Start with the first value instead, and the loop handles the rest (note it starts at i = 2).

Think of max as the current champion: it only changes hands when a bigger value shows up.

The “running champion” mental model: only the current best holds the title; it gets handed off whenever a bigger contender shows up. The figure on the third sub-slide traces the sample run. Starting at 0 is wrong if inputs can be negative (-5 > 0 is false, so -5 would never become max). Starting with the first element is always safe.

The Counter Pattern

Template:

int count = 0;             // always starts at 0

for (...) {
    if (someCondition) {
        count++;           // add 1 only when the condition is met
    }
}

// use count AFTER the loop

A counter is an accumulator that always adds 1, but only when the condition holds.

Example: count how many numbers from 1 to 100 are divisible by 7.

int count = 0;

for (int i = 1; i <= 100; i++) {
    if (i % 7 == 0) {
        count++;
    }
}

IO.println("Divisible by 7: " + count);

Output:

Divisible by 7: 14

The counter is an accumulator where the operation is always +1 and it’s conditional. Point out that count always starts at 0 — unlike max which starts at the first element. Also a good moment to reinforce i % 7 == 0 as the divisibility test (remainder is 0 → divides evenly). The 14 are 7, 14, …, 98.

The Sentinel Pattern

Template:

String input = IO.readln("...");     // read once BEFORE the loop (prime the pump)

while (!input.equals(SENTINEL)) {
    // process input
    input = IO.readln("...");        // read again at the BOTTOM
}

Sentinel loops use while, not for: you don’t know in advance how many values are coming.

Example: read numbers until the user types done, echoing each one.

String line = IO.readln("Enter a number (or 'done'): ");

while (!line.equals("done")) {
    int n = Integer.parseInt(line);
    IO.println("You entered: " + n);
    line = IO.readln("Enter a number (or 'done'): ");
}

IO.println("Finished.");

Sample run:

Enter a number (or 'done'): 8
You entered: 8
Enter a number (or 'done'): 15
You entered: 15
Enter a number (or 'done'): done
Finished.

The check happens before parseInt, so "done" is never converted to a number (which would crash).

Repeat the “prime the pump” explanation from deck 11. The sentinel pattern almost always uses while (not for) because you don’t know in advance how many iterations there will be. The two reads are easy to forget — drill the pattern: read → check → use → read → check → … Point out why the String is checked before Integer.parseInt: parseInt(“done”) would throw a NumberFormatException.

Same Shape: Input Validation

The same read → check → read again shape can keep asking until the input is valid:

String input = IO.readln("Enter a positive number: ");
int n = Integer.parseInt(input);

while (n <= 0) {
    IO.println("That's not positive. Try again.");
    input = IO.readln("Enter a positive number: ");
    n = Integer.parseInt(input);
}

IO.println("Got it: " + n);

Sample run:

Enter a positive number: -4
That's not positive. Try again.
Enter a positive number: 0
That's not positive. Try again.
Enter a positive number: 6
Got it: 6

Here the loop stops on a condition (the input is valid), not on one special value, but the structure is the same: read before the loop, check, read again at the bottom.

This is a very common real-world use case: keep asking until the answer is acceptable. Note that the structure is identical to the sentinel pattern — read before the loop, check, process (in this case, complain), read again at the bottom.

Combining Patterns: Average

Goal: read numbers until done, then print the average.

int sum = 0;      // accumulator
int count = 0;    // counter

String line = IO.readln("Enter a number (or 'done'): ");

while (!line.equals("done")) {
    int n = Integer.parseInt(line);
    sum = sum + n;    // accumulate
    count++;          // count
    line = IO.readln("Enter a number (or 'done'): ");
}

if (count > 0) {
    IO.println("Average: " + (double) sum / count);
} else {
    IO.println("No numbers entered.");
}

Sample run (user enters 3, 7, 1, 4, 2):

Enter a number (or 'done'): 3
Enter a number (or 'done'): 7
Enter a number (or 'done'): 1
Enter a number (or 'done'): 4
Enter a number (or 'done'): 2
Enter a number (or 'done'): done
Average: 3.4
  • Average needs both patterns: an accumulator for the total and a counter for how many, updated in the same pass.
  • (double) sum / count avoids integer division (Lecture 4): 17 / 5 would give 3, not 3.4.
  • The if (count > 0) guard prevents dividing by zero when the user types done right away.

Average = sum / count. You need BOTH an accumulator (for the total) and a counter (for how many). They run in the same loop body — the loop visits each value once, and both patterns update in the same pass. The cast is the deck 04 “cast first, then divide” rule: (double)(sum / count) would still give 3.0. The guard prevents division by zero if the user types “done” immediately.

Multi-Goal Loop

A single loop can track sum, count, and maximum all at once:

int sum = 0;
int count = 0;
int max = Integer.MIN_VALUE;   // smallest possible int

String line = IO.readln("Enter a number (or 'done'): ");

while (!line.equals("done")) {
    int n = Integer.parseInt(line);
    sum = sum + n;
    count++;
    if (n > max) { max = n; }
    line = IO.readln("Enter a number (or 'done'): ");
}

IO.println("Sum: " + sum + ", Count: " + count + ", Max: " + max);

Sample run (user enters -3, -7, -1):

Enter a number (or 'done'): -3
Enter a number (or 'done'): -7
Enter a number (or 'done'): -1
Enter a number (or 'done'): done
Sum: -11, Count: 3, Max: -1

Note

Integer.MIN_VALUE is the smallest int Java can represent (about −2.1 billion), so any real input is at least as large. We use it here instead of “start with the first value” because in a sentinel loop the first input might be done.

Integer.MIN_VALUE solves the “what if all inputs are negative?” problem cleanly. The sample run shows it: if max started at 0, the answer would be 0 (wrong). With MIN_VALUE, it correctly finds -1. If the user types done immediately, max would print as -2147483648 — in real code, guard with count > 0 as on the previous slide.

Identifying the Pattern

When you see a loop problem, ask:

  1. Do I know how many values there will be? If not → Sentinel (while)
  2. Do I need to build up a value? → Accumulator (sum, product, max)
  3. Do I need to count how many meet a condition? → Counter
  4. Do I need both a total and a count? → Both, in the same loop

The first question picks the loop (for or while); the others pick what goes in the body. Real problems often need more than one pattern.

Walk through the decision diagram slowly. Note that the questions are not exclusive: a sentinel loop can contain an accumulator (Combining Patterns: Average). Many real problems combine two or more patterns — average is accumulator + counter, grade stats is accumulator + counter + max. Learning to spot each pattern independently is the first step to composing them correctly.

Putting It Together: Grade Statistics

void printStats(int numStudents) {
    int sum = 0;
    int count = 0;
    int max = Integer.MIN_VALUE;

    for (int i = 1; i <= numStudents; i++) {
        String input = IO.readln("Enter grade for student " + i + ": ");
        int grade = Integer.parseInt(input);
        sum = sum + grade;
        count++;
        if (grade > max) { max = grade; }
    }

    IO.println("Average: " + (double) sum / count);
    IO.println("Highest: " + max);
    IO.println("Total students: " + count);
}
void main() {
    printStats(5);
}

Sample run (grades 88, 92, 75, 64, 95):

Enter grade for student 1: 88
Enter grade for student 2: 92
Enter grade for student 3: 75
Enter grade for student 4: 64
Enter grade for student 5: 95
Average: 82.8
Highest: 95
Total students: 5
  • Accumulator: sum. Counter: count. Maximum: max. All three in one loop.
  • We know the number of students up front, so this is a for loop, not a sentinel loop.

This example puts everything together: a method with a parameter (deck 09), a for loop (deck 12), and three loop patterns running simultaneously (accumulator for sum, counter for count, max tracker). Have students identify which line belongs to which pattern before revealing the bullets. Sharp students will notice count always ends equal to numStudents — it’s there to show the pattern; you could divide by numStudents instead. Calling printStats(0) would divide by zero (prints NaN for a double) — a good “what could go wrong?” question.

Key Takeaways

  • An accumulator starts at the operation’s identity (0 for sum, 1 for product, "" for text) and updates every iteration.
  • A maximum starts at the first value (or Integer.MIN_VALUE), never at 0.
  • A counter starts at 0 and adds 1 only when a condition holds.
  • A sentinel loop uses while: read before the loop, check, read again at the bottom.
  • Patterns combine: average = accumulator + counter in one loop. Use (double) and guard against count = 0.
