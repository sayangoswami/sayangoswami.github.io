Variables — What Are They?

This slide is the conceptual foundation — no syntax, no types, no code yet. The only goal is to give students an intuitive mental model before anything else. Programs need to remember things: a score, a name, a temperature. A variable is just a named place to hold one piece of information. The scoreboard and sticky-note examples are deliberately mundane — the point is that this idea already exists in everyday life. Students already understand “Score: 47” as a label paired with a value. That’s all a variable is.

Before a program can do anything useful, it needs to remember things.

Think about situations where you already use named values without thinking about it:

  • A scoreboard: Score: 47 — the word “Score” is the label; 47 is what’s stored there right now
  • A thermostat: Temperature: 68°F — same idea
  • A name badge: Name: Alice — a label that identifies what the value means

A variable is the same thing inside a program:

A variable is a named container that holds one piece of information.

Your program can:

  • Store a value in it
  • Look at what’s currently inside
  • Change it whenever needed

That’s it. Everything else — types, syntax, declarations — is just the details of how Java makes you write this down.

Why Do Programs Need Variables?

The recipe analogy works well here — and keep it as plain text, no code. A recipe hardcoded for 2 people has to be rewritten by hand every time you want to change the serving size. With a variable, you change one number and every quantity updates. The point is conceptual: variables let one set of instructions work for many different inputs. The code version of this will make sense once students have seen declarations, printing, and arithmetic.

Imagine a recipe written for exactly 2 people:

- 2 cups of flour
- 1 cup of sugar
- 3 eggs

Want to make it for 4? You cross everything out and rewrite it.

Now imagine a version with a note at the top:

Servings: 2

- [servings] cups of flour
- [servings / 2] cups of sugar
- [servings * 2 - 1] eggs

Change the one number at the top → every quantity updates automatically.

That note at the top is a variable. One change, everywhere.

Variables in Algebra vs. Programming

Students have seen variables in algebra — start there. The similarities are real and worth naming: a variable is a named placeholder for a value. Then get into the differences. In algebra, the variable is unknown and you solve for it. In programming, you are the one who sets the value — the computer doesn’t “solve” for anything. Also: algebra variables are almost always single letters; programming variables have full descriptive names. And the biggest one: in programming, a variable’s value can change.

You have seen variables before — in algebra.

Algebra Programming
What it is Named placeholder for a value Named placeholder for a value
Who sets the value You solve for it You tell the computer
Names x, y, z score, temperature, userName
Can it change? No — x is fixed once solved Yes — can be updated anytime
Has a type? No Yes — must declare one

The core idea is the same. The rules are different.

Think of Variables as Labeled Cups

The Starbucks analogy is intuitive and memorable. At a Starbucks counter, your cup has your name written on it (so the barista knows whose order it is), a size (tall, grande, venti — that’s the type), and whatever drink is actually inside (the value). A variable works exactly the same way. The name identifies it. The type says what kind of thing it can hold. The value is what’s actually in there right now. And just like a cup can be emptied and refilled, a variable’s value can change.

When you order at Starbucks, your cup has three things:

  1. Your name written on it — so the barista knows whose it is
  2. A size — tall, grande, venti — that determines what it can hold
  3. The actual drink inside

A variable works the same way:

Cup Variable
Name on cup Variable name (score, userName)
Cup size / type Data type (int, double, String)
Drink inside The value stored (42, 3.14, "Alice")

And just like a cup can be emptied and refilled — a variable’s value can change.

Why Do Variables Have Types?

The food container analogy gets at the intuition. Different foods need different containers — you wouldn’t put soup in a paper bag. The container type isn’t arbitrary: it’s determined by what you’re storing. Same with data. Types tell the computer what kind of data the variable holds, which determines what operations make sense on it.

Different foods need different containers:

  • Coffee → cup
  • Burger → box or wrapper
  • Fries → paper bag
  • Ice cream → cone or cup

You wouldn’t put soup in a paper bag. The container depends on what you’re storing.

Data is the same way:

Data Java type
Whole numbers int
Decimal numbers double
True / false boolean
Text String

The Four Basic Types

Clean reference slide. Emphasize: String is capitalized — it’s different from the other three and we’ll talk more about it later. boolean values are only two: true or false — no quotes, all lowercase. “42” (String) and 42 (int) look similar but are very different — you can’t do math on “42”.

Type Holds Examples
int Whole numbers 0, 42, -7, 1_000_000
double Decimal numbers 3.14, -0.5, 98.6
boolean True or false true, false
String Text "Hello", "Alice", "42"

A few things worth noting:

  • String is capitalized — it’s special. More on this soon.
  • true and false are lowercase, no quotes.
  • "42" (String) and 42 (int) are not the same. You cannot do arithmetic on "42".

Declaring and Initializing Variables

Walk through the syntax pattern carefully. Type → name → equals → value → semicolon. Declaration is announcing the variable to the compiler. Initialization is giving it its first value. You can do both at once (which is the norm) or separately. If you declare without initializing and then try to use the variable, Java will give you a compile error — it won’t guess a default value for you (for local variables). Show all four types.

The pattern:

type  name  =  value  ;
int score = 0;
double temperature = 98.6;
boolean isRaining = true;
String name = "Alice";

You can also declare first and assign later:

int score;        // declared — no value yet
score = 100;      // now it has a value

Warning

You cannot use a variable before giving it a value. Java will refuse to compile.

int score;
IO.println(score);   // ERROR: variable score might not have been initialized

Printing the Value of a Variable

Students have seen IO.println with literal text in quotes. Now show that you can pass a variable directly — no quotes. The output is whatever value the variable currently holds. Walk through all four types. This is intentionally simple: declare a variable, print it. No operations yet.

You already know how to print text in quotes.

You can also pass a variable directly to IO.println — it prints whatever value the variable holds.

void main() {
    int score = 100;
    IO.println(score);         // prints: 100

    double temperature = 98.6;
    IO.println(temperature);   // prints: 98.6

    boolean isRaining = false;
    IO.println(isRaining);     // prints: false

    String name = "Alice";
    IO.println(name);          // prints: Alice
}

No quotes around the variable name — just the name itself.

Note

Notice: IO.println("score") would print the word score. IO.println(score) prints the value stored in the variable.

The Assignment Operator — Not What You Think

This is a genuine conceptual stumbling block. In mathematics, = means “these two things are equal.” In Java, = means “take the value on the right and store it in the variable on the left.” They look the same but behave completely differently. The clearest demonstration is a = a + 1: mathematically nonsense (subtract a from both sides: 0 = 1), but in programming it’s completely normal and means “add 1 to whatever is currently in a”. Do this on the board slowly: if a was 5, evaluate the right side (5+1=6), then store 6 into a. Now a is 6.

In algebra, = means “these are equal” — a statement of fact.

In Java, = means “store this value” — a command.

These are completely different things.

Algebra:

a = a + 1

Subtract a from both sides:

0 = 1   ← impossible

Java:

a = a + 1;

“Take the current value of a, add 1 to it, store the result back in a.”

int a = 5;
a = a + 1;           // a is now 6
a = a + 1;           // a is now 7
IO.println(a);       // prints 7

Reassigning Variables

Show that a variable holds the MOST RECENT value assigned to it. Trace through the program step by step — this is a good opportunity to introduce the idea of tracing, which will be a recurring skill throughout the course. Emphasize: println shows what’s in the variable at that moment in time, not some average or history.

Once declared, a variable’s value can be changed:

int score = 0;
IO.println(score);       // prints 0

score = 10;
IO.println(score);       // prints 10

score = score + 5;
IO.println(score);       // prints 15

The variable always holds the most recently assigned value.

Let’s trace it step by step:

Line What happens score
int score = 0; Declared and set to 0 0
score = 10; Overwritten with 10 10
score = score + 5; 10 + 5 = 15, stored back 15

Naming Variables

Algebra uses single letters because equations are short. Programs are long and read by humans — descriptive names are essential. Walk through the rules, then the conventions. camelCase is the Java convention for variable names: start lowercase, capitalize each subsequent word. Emphasize that meaningful names are not optional polish — they are part of writing readable, professional code.

In algebra, single letters are fine: x, y, z. In programs, names should describe what the variable holds.

Less clear:

int n = 30;
double t = 98.6;
String s = "Alice";

Better:

int numberOfStudents = 30;
double bodyTemperature = 98.6;
String studentName = "Alice";

Rules (the compiler enforces these):

  • Must start with a letter (not a digit)
  • Can contain letters, digits, and _
  • Case-sensitive: score and Score are different variables
  • Cannot be a Java keyword (int, void, true, etc.)

Convention (Java style, not enforced but expected):

  • Use camelCase: firstName, totalScore, isLoggedIn
  • Be descriptive: playerCount beats n

Programs That Always Do the Same Thing

Motivate input before introducing the tool. Every program written so far is completely deterministic — same code, same output, every time. That’s fine for learning but useless for anything real. The question to pose to the class: what if we want a program that can greet different people, or do different things depending on who’s using it? That requires input. Don’t introduce any new syntax here — just make students feel the problem.

Every program we have written so far does exactly the same thing every time it runs.

void main() {
    IO.println("Hello, Alice!");
    IO.println("Welcome to the course.");
}

Run it a hundred times — same output, every time.

That is fine for practice. But real programs need to respond to the person using them.

What if we want to greet whoever is actually sitting at the keyboard?

To do that, the program needs to ask — and the user needs to answer.

That is what input is.

What Is Input?

Pure concept — no code yet. Students already know about output (IO.println sends information from the program to the screen). Input is the other direction: information flows from the user to the program. The two-arrow figure makes this concrete. Spend time here — the mental model of “two directions of information flow” is foundational for everything interactive they will ever write.

So far, information has only flowed one direction:

Program → Screen — using IO.println

Input is the other direction:

User → Program — the user types something; the program receives it

Output (IO.println)

The program sends information out. The screen shows it.

Input (IO.readln)

The user types information in. The program receives it.

Together, these two directions let you write programs that have a conversation with the user.

IO.readln — The Simplest Form

Introduce the mechanics first, without a prompt string — so students can focus entirely on what readln DOES. When Java hits IO.readln(), execution stops. A cursor blinks. The program waits. The user types something and presses Enter. Whatever they typed is produced as a String. That’s it. Walk through the sample run line by line. Emphasize: the program is paused — it is not broken, it is not slow, it is waiting for the user.

IO.readln() pauses the program and waits for the user to type a line of text.

void main() {
    String name = IO.readln();
    IO.println(name);
}

When Java reaches IO.readln():

  1. The program stops
  2. A cursor appears — the program is waiting
  3. The user types something and presses Enter
  4. IO.readln produces the typed text as a String
  5. That String is stored in name
  6. The program continues

Sample run:

Alice
Alice

Warning

If you do not store the result in a variable, it is gone the instant the line finishes — the program read the input and immediately forgot it.

Adding a Prompt

The no-prompt form works but is confusing in practice — users see a blank screen and have no idea what to type. The prompt string solves this. It is printed before the program pauses, giving the user a cue. Key point: the prompt does not change what gets produced — it is purely for the human’s benefit. Show a side-by-side comparison of sample runs so the difference is vivid. This is the form students will use in all their programs.

Without a prompt, the user just sees a blinking cursor — and has no idea what to type.

IO.readln accepts an optional prompt: a message to display before waiting.

void main() {
    String name = IO.readln("What is your name? ");
    IO.println(name);
}

Sample run:

What is your name? Alice
Alice

The prompt is printed first — then the program pauses for input.

Without prompt:

▌

(User sees a blank cursor — confused)

With prompt:

What is your name? ▌

(User knows exactly what to type)

Note

The prompt does not affect what the program receives. It is a message for the user, not part of the input.

Note

IO.readln always produces a String — even if the user types 42, the program receives the text "42", not the number. Converting it to a number is coming in the next lecture.

Putting It Together

A complete example using multiple variables, IO.readln, and IO.println. No combining of strings yet — just store and print. Trace through it with the class. Reinforce: execution is top to bottom; each variable holds the most recently assigned value; printing a variable prints its current value.

void main() {
    String name = IO.readln("Enter your name: ");
    String city = IO.readln("What city are you from? ");

    IO.println("Name:");
    IO.println(name);
    IO.println("City:");
    IO.println(city);
}

Sample run:

Enter your name: Jordan
What city are you from? Baltimore
Name:
Jordan
City:
Baltimore

Each piece of information prints on its own line. Soon we will learn how to combine values onto a single line — that is the next lecture.

Why Does the Type Matter?

Now that students have written declarations and feel some comfort with the syntax, this slide gives the intuition for why types exist — without any technical jargon. The key point: the type changes what operations make sense. You can add two ints. You can’t add two names. The computer uses the type to figure out what “+” even means.

2 + 3 and 2.0 + 3.0 look the same to us. The computer handles them differently.

  • 2 + 3 — whole-number addition. The result is always exact.
  • 2.0 + 3.0 — decimal addition. Works differently, and can occasionally produce small surprises.
IO.println(0.1 + 0.2);   // you might expect 0.3 ...
                          // the computer prints 0.30000000000000004

This is not a bug — it’s just how decimal math works on a computer.

The type also tells the computer which operations make sense:

  • You can multiply two int values.
  • You cannot multiply two String values — what would "Alice" * "Bob" even mean?

The type is not just a label for you. It tells the computer what kind of thing the variable holds.

Should You Always Use double for Numbers?

Students sometimes wonder: if double can hold whole numbers too (5.0 is a valid double), why ever use int? The key reasons are semantic clarity and the decimal surprise shown above. Don’t mention memory or performance — that’s too deep for this stage. Focus on meaning: an int says “this is always a whole number.” That’s both clearer and safer.

double can store whole numbers too — 5.0 is perfectly valid.

So why use int at all?

Whole numbers stay exact. Decimal math can have small surprises (see previous slide). If a value is always a whole number, int guarantees it stays clean.

The type says what you mean.

double numberOfStudents = 2.7;  // What does this even mean?
int numberOfStudents = 27;      // Clear and correct

You cannot have 2.7 students. Using int communicates that — and if you accidentally compute a decimal result, Java will warn you.

Tip

Rule of thumb: Use int for things you count. Use double for things you measure.

  • Count: students, quiz scores, laps → int
  • Measure: temperature, GPA, price → double

Common Mistakes

These are the mistakes you will see most frequently in the first few weeks. Go through each one briefly and show what error it produces or what wrong output it causes. The goal is to make students recognize these errors when they see them, not to memorize a list.

1. Using a variable before giving it a value

int score;
IO.println(score);   // ERROR — score has no value yet

2. Wrong type for the value

int name = "Alice";   // ERROR — can't store text in an int

3. Forgetting to store IO.readln’s result

IO.readln("Enter your name: ");   // the returned value is lost
IO.println(name);                 // ERROR — name was never declared

4. Confusing = (assignment) with equality

score = 10;    // stores 10 in score ✓
score == 10;   // checks if score equals 10 — but does nothing here (coming later)

5. Case errors

int playerScore = 0;
IO.println(PlayerScore);   // ERROR — Java is case-sensitive
