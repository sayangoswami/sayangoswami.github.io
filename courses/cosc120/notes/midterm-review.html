Midterm Review

COSC120: Introduction to Computer Science I

What the Midterm Covers

Set expectations first. The midterm stops at Strings: no methods beyond main, no loops. Every problem is “write the whole void main()” graded by CodeCheck on exact output, so the spec-reading habit matters as much as the Java.

Everything up to and including Strings:

Topic You should be able to…
Variables and I/O read ints and Strings with IO.readln(), print with IO.println()
Arithmetic use + - * / %, integer vs. double division
Conditionals write if / else if / else chains in the right order
Nested conditionals put an if inside another if when one decision depends on another
Boolean logic combine conditions with &&, ||, !
Strings .length(), .substring(), .charAt(), .toUpperCase(), .toLowerCase(), .equals()

The exam has two write-the-program problems:

  1. An if/else problem with numbers
  2. An if/else problem with Strings

Recap — The else if Chain

The single most important idea: Java checks top to bottom and runs only the FIRST true branch. Everything below it is skipped. Ordering bugs come from forgetting this.

if (condition1) {
    // runs if condition1 is true
} else if (condition2) {
    // runs only if condition1 was false AND condition2 is true
} else {
    // runs if every condition above was false
}
  • Java checks conditions top to bottom.
  • Only the first true branch runs. The rest are skipped.
  • So put the special cases first (invalid input, “all equal”, “origin”, …).

Recap — Combining Conditions

Operator Meaning true when…
a && b AND both are true
a || b OR at least one is true
!a NOT a is false

Each side of && / || must be a complete comparison:

x > 0 && x < 10      // correct
x > 0 && x % 2      // does not compile
x > 0 && < 10        // does not compile

Recap — String Toolkit

Have students say the result of each call out loud before revealing. The two traps: substring’s end index is exclusive, and toUpperCase returns a NEW string rather than changing s.

For String s = "Maryland"; (length 8, indexes 0–7):

Call Result
s.length() 8
s.substring(0, 4) "Mary" (end index not included)
s.substring(4) "land" (from index 4 to the end)
s.substring(0, 1) "M" (first character as a String)
s.charAt(2) 'r'
s.toUpperCase() "MARYLAND" (s itself is unchanged)

Compare Strings with .equals(), never ==:

if (answer.equals("yes")) { ... }

Warm-up 1 — Trace It

Paper only. n = 15 prints “Three” because 15 % 3 == 0 is checked first, so 15 never reaches the && branch. Make the point that the order decides the answer. n = 10 prints “Five”; n = 7 prints “7 is plain”.

What does this print when n is 15? 10? 7?

void main() {
    int n = Integer.parseInt(IO.readln());

    if (n % 3 == 0) {
        IO.println("Three");
    } else if (n % 5 == 0) {
        IO.println("Five");
    } else if (n % 3 == 0 && n % 5 == 0) {
        IO.println("Both");
    } else {
        IO.println(n + " is plain");
    }
}

Answers: 15 → Three · 10 → Five · 7 → 7 is plain

The "Both" branch can never run. Any number divisible by 3 is caught by the first branch. Fix: move the && test to the top.

Warm-up 2 — Spot the Bugs

Three bugs: (1) == on Strings; (2) toLowerCase result thrown away; (3) substring(1, 2) gets the second character, not the first. Have students find all three before revealing.

The program should read a word and print Starts with a vowel if its first letter is a or e (any case). Find three bugs.

void main() {
    String word = IO.readln();
    word.toLowerCase();
    String first = word.substring(1, 2);

    if (first == "a" || first == "e") {
        IO.println("Starts with a vowel");
    } else {
        IO.println("Starts with a consonant");
    }
}
  1. word.toLowerCase(); throws its result away. Use word = word.toLowerCase();
  2. substring(1, 2) is the second character. Use substring(0, 1).
  3. == on Strings. Use first.equals("a") || first.equals("e").

Practice: if/else with Numbers

Practice 1 — Point Location

Give students about 8 minutes. Walk around and look for the ordering mistake: students who check x > 0 && y > 0 first are fine, but students who check y == 0 before the origin case will print “On the x-axis” for (0, 0).

Read two ints, x then y (no prompts). Print where the point is:

Condition Output
both are 0 Origin
only y is 0 On the x-axis
only x is 0 On the y-axis
x > 0, y > 0 Quadrant I
x < 0, y > 0 Quadrant II
x < 0, y < 0 Quadrant III
x > 0, y < 0 Quadrant IV

Example: input -3 and 5 → Quadrant II

Java
Terminal

Practice 1 — Solution

void main() {
    int x = Integer.parseInt(IO.readln());
    int y = Integer.parseInt(IO.readln());

    if (x == 0 && y == 0) {
        IO.println("Origin");
    } else if (y == 0) {
        IO.println("On the x-axis");
    } else if (x == 0) {
        IO.println("On the y-axis");
    } else if (x > 0 && y > 0) {
        IO.println("Quadrant I");
    } else if (x < 0 && y > 0) {
        IO.println("Quadrant II");
    } else if (x < 0) {
        IO.println("Quadrant III");
    } else {
        IO.println("Quadrant IV");
    }
}

Why the origin goes first: if y == 0 were checked first, (0, 0) would print On the x-axis.

Why else if (x < 0) is enough for Quadrant III: by that line we already know neither is 0 and y is not positive.

Practice 2 — Order of Three

The trap is the word “strictly”. 1, 1, 2 is Mixed, not Increasing. Students who write a <= b && b <= c get it wrong. Also test 7, 7, 7: All equal must be checked before the others (though with strict < it would fall to Mixed anyway, so the bug shows up as a wrong label).

Read three ints a, b, c (no prompts). Print:

  • All equal: all three are the same
  • Increasing: a < b < c, strictly
  • Decreasing: a > b > c, strictly
  • Mixed: anything else

Examples: 2 5 9 → Increasing · 4 1 4 → Mixed · 1 1 2 → Mixed

Java
Terminal

Practice 2 — Solution

void main() {
    int a = Integer.parseInt(IO.readln());
    int b = Integer.parseInt(IO.readln());
    int c = Integer.parseInt(IO.readln());

    if (a == b && b == c) {
        IO.println("All equal");
    } else if (a < b && b < c) {
        IO.println("Increasing");
    } else if (a > b && b > c) {
        IO.println("Decreasing");
    } else {
        IO.println("Mixed");
    }
}

Common mistake: writing a < b < c. Java won’t compile it. You need two comparisons joined with &&: a < b && b < c.

Practice: if/else with Strings

Practice 3 — Username Check

Two ideas here: checking rules in a fixed order (else if), and building a new String from pieces. “ab” should print ”Too short”, not ”Cannot start with ”, because rule 1 comes first. That’s the ordering lesson again.

Read a username (no prompts). Check these rules in order and print the message for the first one that fails:

  1. fewer than 5 characters → Too short
  2. more than 12 characters → Too long
  3. starts with _ → Cannot start with _

If all pass, print Welcome, followed by the name with the first letter upper case and the rest lower case.

Examples: jORDAN → Welcome, Jordan · _ghost → Cannot start with _ · _ab → Too short

Java
Terminal

Practice 3 — Solution

void main() {
    String name = IO.readln();

    if (name.length() < 5) {
        IO.println("Too short");
    } else if (name.length() > 12) {
        IO.println("Too long");
    } else if (name.substring(0, 1).equals("_")) {
        IO.println("Cannot start with _");
    } else {
        String fixed = name.substring(0, 1).toUpperCase()
                     + name.substring(1).toLowerCase();
        IO.println("Welcome, " + fixed);
    }
}

name.substring(0, 1) is the first character as a String, so we can compare it with .equals().

Read a phone number typed as digits only, e.g. 4105551234 (no prompts).

  • Not exactly 10 characters → print Invalid number
  • Otherwise print (AAA) BBB-CCCC, then on the next line Maryland if the area code is 410, 443, 240, or 301, else Out of state
Input:  4105551234        Input:  2125550199
Output: (410) 555-1234    Output: (212) 555-0199
        Maryland                  Out of state
Java
Terminal

Practice 4 — Solution

void main() {
    String phone = IO.readln();

    if (phone.length() != 10) {
        IO.println("Invalid number");
    } else {
        String area = phone.substring(0, 3);
        IO.println("(" + area + ") " + phone.substring(3, 6) + "-" + phone.substring(6));

Practice: Nested if/else

Why Nest?

Frame the whole session around one question students should ask before writing any code: is the second decision a different value of the same thing (else if), or does it only make sense once the first decision is known (nested if)? Every problem in this deck has at least one decision that only makes sense inside another branch.

An if goes inside another if when the second question only makes sense after the first one is answered.

if (outer condition) {
    if (inner condition) {
        // outer true AND inner true
    } else {
        // outer true AND inner false
    }
} else {
    // outer false: the inner question is never asked
}
  • Different values of the same thing (score → grade)? Use an else if chain.
  • One answer changes which question comes next (member? → then which fee?)? Nest.

Plan Before You Type

Have students do this on paper for the first problem. Most of the bugs from the midterm came from starting to type before deciding what the outer question was, then patching cases with && until the logic broke.

  1. What is the first question? Usually: is the input valid? Or: which category/mode is it?
  2. For each answer, what do I need to ask next? That becomes the inner if.
  3. Write the outer skeleton first, with empty braces. Then fill each branch.
  4. Indent one level per nesting level. If you can’t tell which else goes with which if, neither can the reader.
if (days <= 0) {
    // step 1: no fee, done
} else if (member.equals("yes")) {
    // step 2: member rules go here
} else {
    // step 2: non-member rules go here
}

Warm-up 3 — Trace the Nesting

Paper only. a = 5, b = 2 prints “B”; a = 5, b = 9 prints “C”; a = -1, b = 9 prints “D”. The point: the inner if/else is a single statement of the outer if, so for a = -1 the inner code is skipped completely. Ask what happens for a = -1, b = -1 (still D, because the inner question is never asked).

What does this print for a = 5, b = 2? a = 5, b = 9? a = -1, b = 9?

if (a > 0) {
    if (b < a) {
        IO.println("B");
    } else {
        IO.println("C");
    }
} else {
    IO.println("D");
}

Answers: 5, 2 → B · 5, 9 → C · -1, 9 → D

When a is -1, the inner if is never even looked at. The outer else runs instead.

Nested if/else with Numbers

Practice 5 — Sign and Parity

Warm-up. The outer decision is the sign; the even/odd question is asked inside each branch. The trap: students who write n % 2 == 1 for odd get -7 wrong, because -7 % 2 is -1 in Java. Testing == 0 for even and using else avoids it.

Read one integer and describe it with two facts: its sign and whether it is even or odd.

  • If the number is 0, print Zero.
  • If it is positive, print Positive even or Positive odd.
  • If it is negative, print Negative even or Negative odd.

Careful: in Java, -7 % 2 is -1, not 1. Test for even with n % 2 == 0.

Input (no prompts): One line containing one int.

Examples

Input Output
8 Positive even
-7 Negative odd
0 Zero
Java
Terminal

Practice 5 — Solution

void main() {
    int n = Integer.parseInt(IO.readln());
    if (n == 0) {
        IO.println("Zero");
    } else if (n > 0) {
        if (n % 2 == 0) {
            IO.println("Positive even");
        } else {
            IO.println("Positive odd");
        }
    } else {
        if (n % 2 == 0) {
            IO.println("Negative even");
        } else {
            IO.println("Negative odd");
        }
    }
}

Common mistake: testing odd with n % 2 == 1. For -7, n % 2 is -1, so that test is false and -7 would be called even. Test n % 2 == 0 and let else handle odd.

Practice 6 — Phone Battery

The outer if splits on the String, the inner decisions are on the number. Point out that the inner chain on the ‘no’ side is an ordinary else-if chain, just indented one level. Ordering matters inside it: <= 5 must come before <= 20.

Read a phone’s battery level (0 to 100) and whether it is plugged in (yes or no). Print a status message:

  • Plugged in (yes):
    • level is 100 → Fully charged
    • otherwise → Charging: <level>%
  • Not plugged in (no):
    • level is 5 or less → Critical: plug in now
    • level is 20 or less → Low battery: <level>%
    • otherwise → Battery: <level>%

Input (no prompts): Two lines: an int (the battery level, 0 to 100), then a String (yes or no, always lower case).

Examples

Input Output
42
yes		 Charging: 42%
15
no		 Low battery: 15%
3
no		 Critical: plug in now
Java
Terminal

Practice 6 — Solution

void main() {
    int level = Integer.parseInt(IO.readln());
    String plugged = IO.readln();
    if (plugged.equals("yes")) {
        if (level == 100) {
            IO.println("Fully charged");
        } else {
            IO.println("Charging: " + level + "%");
        }
    } else {
        if (level <= 5) {
            IO.println("Critical: plug in now");
        } else if (level <= 20) {
            IO.println("Low battery: " + level + "%");
        } else {
            IO.println("Battery: " + level + "%");
        }
    }
}

Order inside the inner chain matters. If level <= 20 came first, a level of 3 would print Low battery: 3% and the critical message could never run.

Practice 7 — Elevator

Validity check first (an || of four comparisons), then the direction, then a nested singular/plural decision inside each direction. Watch for students who compute requested - current for both directions and print a negative number.

A building has floors 1 through 10. Read the floor the elevator is on and the floor someone requested.

  • If either floor is outside 1–10, print Invalid floor.
  • Otherwise, if they are the same floor, print Already on floor <floor>.
  • Otherwise, print Going up or Going down, followed by how many floors it moves. Use the word floor when it moves exactly 1, and floors otherwise.

Input (no prompts): Two lines, each containing one int: the current floor, then the requested floor.

Examples

Input Output
3
7		 Going up 4 floors
5
4		 Going down 1 floor
6
6		 Already on floor 6
Java
Terminal

Practice 7 — Solution

void main() {
    int current = Integer.parseInt(IO.readln());
    int requested = Integer.parseInt(IO.readln());
    if (current < 1 || current > 10 || requested < 1 || requested > 10) {
        IO.println("Invalid floor");
    } else if (current == requested) {
        IO.println("Already on floor " + current);
    } else if (requested > current) {
        int moves = requested - current;
        if (moves == 1) {
            IO.println("Going up 1 floor");
        } else {
            IO.println("Going up " + moves + " floors");
        }
    } else {
        int moves = current - requested;
        if (moves == 1) {
            IO.println("Going down 1 floor");
        } else {
            IO.println("Going down " + moves + " floors");
        }
    }
}

Each comparison needs both sides. current < 1 || > 10 does not compile. Write current < 1 || current > 10.

Practice 8 — State of Water

Same shape inside each outer branch, with different numbers. Converting the unit to upper case once, right after reading it, means every later .equals() only has to check one spelling.

Read a temperature and its unit, then print whether water at that temperature is Ice, Liquid water, or Steam. The unit is C (Celsius) or F (Fahrenheit), typed in either upper or lower case.

Unit Ice Liquid water Steam
C 0 or below above 0 and below 100 100 or above
F 32 or below above 32 and below 212 212 or above

If the unit is anything else, print Unknown unit.

Examples

Input Output
25
C		 Liquid water
212
f		 Steam
50

Practice 8 — Solution

void main() {
    int temp = Integer.parseInt(IO.readln());
    String unit = IO.readln().toUpperCase();

            IO.println("Ice");

Nested if/else with Numbers and Strings

Practice 9 — Library Late Fee

Three levels of decision: late at all? member or not? over the cap? The cap check is nested inside each membership branch because the cap and the rate depend on membership. Boundary to test: exactly at the cap (10 days for a member) prints no ‘(maximum)’.

A library charges for late books. Read how many days late a book is and whether the borrower is a member (yes or no).

  • If the book is 0 or fewer days late, print No fee.
  • Members pay $1 per day, up to a maximum of $10.
  • Non-members pay $2 per day, up to a maximum of $20.

If the per-day fee would be more than the maximum, the borrower pays the maximum instead and the line ends with (maximum). A fee exactly equal to the maximum does not get (maximum).

Input (no prompts): Two lines: an int (days late), then a String (yes or no, always lower case).

Examples

Input Output
3
yes		 Fee: $3
4
no		 Fee: $8
15
yes		 Fee: $10 (maximum)
Java
Terminal

Practice 9 — Solution

void main() {
    int days = Integer.parseInt(IO.readln());
    String member = IO.readln();
    if (days <= 0) {
        IO.println("No fee");
    } else if (member.equals("yes")) {
        int fee = days * 1;
        if (fee > 10) {
            IO.println("Fee: $10 (maximum)");
        } else {
            IO.println("Fee: $" + fee);
        }
    } else {
        int fee = days * 2;
        if (fee > 20) {
            IO.println("Fee: $20 (maximum)");
        } else {
            IO.println("Fee: $" + fee);
        }
    }
}

Test the boundary. A member who is exactly 10 days late owes $10, which is not more than the maximum, so the output is Fee: $10, without (maximum).

Practice 10 — Speeding Fine

New idea: a nested block that does more than print. The else branch computes ‘over’, picks a fine with a chain, then adjusts it with a separate if. Point out that ‘int fine;’ is declared before the chain so every branch can assign it. Also: three input lines, count the readln calls.

Read a speed limit, a driver’s speed, and whether they were in a school zone (yes or no).

If the driver was at or under the limit, print No ticket. Otherwise, work out how many mph over the limit they were and the fine:

mph over the limit Fine
1 to 10 $50
11 to 20 $100
more than 20 $200

In a school zone the fine is doubled.

Input (no prompts): Three lines: an int (the speed limit), an int (the driver’s speed), then a String (yes or no, always lower case).

Examples

Input Output
30
35
no		 Over by 5 mph
Fine: $50
25
40
yes		 Over by 15 mph
Fine: $200
55
55
no		 No ticket
Java
Terminal

Practice 10 — Solution

void main() {
    int limit = Integer.parseInt(IO.readln());
    int speed = Integer.parseInt(IO.readln());
    String schoolZone = IO.readln();
    if (speed <= limit) {
        IO.println("No ticket");
    } else {
        int over = speed - limit;
        int fine;
        if (over <= 10) {
            fine = 50;
        } else if (over <= 20) {
            fine = 100;
        } else {
            fine = 200;
        }
        if (schoolZone.equals("yes")) {
            fine = fine * 2;
        }
        IO.println("Over by " + over + " mph");
        IO.println("Fine: $" + fine);
    }
}

Two separate decisions inside the else. The fine chain and the school-zone check are not one else if chain. A school-zone driver still needs a base fine first, so the doubling is its own if after the chain.

Practice 11 — Thermostat

This is where nested vs. flattened matters. A student who writes ‘else if (mode.equals(“heat”) && current < target)’ and then ‘else if (mode.equals(“cool”) && …)’ sends heat-mode-already-warm to the next branch and eventually prints ‘Invalid mode’. Nesting keeps ‘which mode?’ separate from ‘what does that mode do?’.

A smart thermostat reads the current temperature, the target temperature, and its mode. The mode is heat, cool, or off, typed in any mix of upper and lower case.

  • off → System off
  • heat → if the current temperature is below the target, Heating to <target>; otherwise Idle
  • cool → if the current temperature is above the target, Cooling to <target>; otherwise Idle
  • any other mode → Invalid mode

Input (no prompts): Three lines: an int (current temperature), an int (target temperature), then a String (the mode).

Examples

Input Output
64
70
heat		 Heating to 70
75
70
COOL		 Cooling to 70
72
70
Heat		 Idle
Java
Terminal

Practice 11 — Solution

void main() {
    int current = Integer.parseInt(IO.readln());
    int target = Integer.parseInt(IO.readln());
    String mode = IO.readln().toLowerCase();
    if (mode.equals("off")) {
        IO.println("System off");
    } else if (mode.equals("heat")) {
        if (current < target) {
            IO.println("Heating to " + target);
        } else {
            IO.println("Idle");
        }
    } else if (mode.equals("cool")) {
        if (current > target) {
            IO.println("Cooling to " + target);
        } else {
            IO.println("Idle");
        }
    } else {
        IO.println("Invalid mode");
    }
}

Don’t flatten it with &&. With else if (mode.equals("heat") && current < target), a heater that is already warm falls through to the next branches and ends up printing Invalid mode instead of Idle.

Nested if/else with Strings

Practice 12 — Compare Two Words

Inner chain order is the lesson: the exact .equals() check must come before the case-insensitive one, because identical words also match ignoring case. Also print the original word, not a lower-cased copy.

Read two words and compare them.

  • If they have the same length:
    • exactly the same (same letters, same case) → Identical
    • the same if you ignore upper/lower case → Same word, different case
    • otherwise → Same length, different words
  • If they have different lengths, print the longer word followed by is longer.

Input (no prompts): Two lines, each containing one String (a single word, no spaces).

Examples

Input Output
Java
java		 Same word, different case
cat
dog		 Same length, different words
apple
kiwi		 apple is longer
Java
Terminal

Practice 12 — Solution

void main() {
    String first = IO.readln();
    String second = IO.readln();
    if (first.length() == second.length()) {
        if (first.equals(second)) {
            IO.println("Identical");
        } else if (first.toLowerCase().equals(second.toLowerCase())) {
            IO.println("Same word, different case");
        } else {
            IO.println("Same length, different words");
        }
    } else {
        if (first.length() > second.length()) {
            IO.println(first + " is longer");
        } else {
            IO.println(second + " is longer");
        }
    }
}

Check Identical first. "hello" and "hello" are also equal when you ignore case. If the case-insensitive test came first, identical words would print Same word, different case.

Practice 13 — Rock, Paper, Scissors

The payoff of checking invalid and tie first: inside each of player 1’s branches there are only two possible player 2 moves left, so one if/else decides it. Storing the validity checks in boolean variables keeps the first condition readable.

Read the moves of two players. Each move is rock, paper, or scissors, typed in any mix of upper and lower case.

  • If either move is not one of those three words, print Invalid move.
  • Otherwise, if both moves are the same, print Tie.
  • Otherwise, decide the winner: rock beats scissors, scissors beats paper, paper beats rock. Print Player 1 wins or Player 2 wins.

Hint: once you know the moves are valid and different, look at player 1’s move first. For each of player 1’s three moves there is exactly one player 2 move that loses to it.

Input (no prompts): Two lines, each containing one String: player 1’s move, then player 2’s move.

Examples

Input Output
rock
scissors		 Player 1 wins
Paper
SCISSORS		 Player 2 wins
rock
Rock		 Tie
Java
Terminal

Practice 13 — Solution

void main() {
    String p1 = IO.readln().toLowerCase();
    String p2 = IO.readln().toLowerCase();
    boolean p1Valid = p1.equals("rock") || p1.equals("paper") || p1.equals("scissors");
    boolean p2Valid = p2.equals("rock") || p2.equals("paper") || p2.equals("scissors");
    if (!p1Valid || !p2Valid) {
        IO.println("Invalid move");
    } else if (p1.equals(p2)) {
        IO.println("Tie");
    } else if (p1.equals("rock")) {
        if (p2.equals("scissors")) {
            IO.println("Player 1 wins");
        } else {
            IO.println("Player 2 wins");
        }
    } else if (p1.equals("paper")) {
        if (p2.equals("rock")) {
            IO.println("Player 1 wins");
        } else {
            IO.println("Player 2 wins");
        }
    } else {
        if (p2.equals("paper")) {
            IO.println("Player 1 wins");
        } else {
            IO.println("Player 2 wins");
        }
    }
}

Why the inner else is safe: by the time we’re inside p1.equals("rock"), we already know p2 is valid and is not rock, so if it’s not scissors it must be paper.

Practice 14 — Days in a Month

Strings + nesting + capitalization. Only February has an inner decision. The capitalization line uses the same substring(0,1).toUpperCase() + substring(1) pattern from the Strings lecture. Since every valid month is exactly 3 letters, substring is safe for all inputs we test; mention that an empty input would crash it.

Read a three-letter month abbreviation (jan, feb, …, dec, typed in any mix of upper and lower case) and whether the year is a leap year (yes or no). Print how many days that month has:

  • feb → 29 in a leap year, 28 otherwise
  • apr, jun, sep, nov → 30
  • jan, mar, may, jul, aug, oct, dec → 31
  • anything else → print Unknown month

Print the month with its first letter upper case and the other two lower case, e.g. Feb has 29 days.

Input (no prompts): Two lines, each containing one String: the month abbreviation, then yes or no (always lower case). The second line is always present, even though only February uses it.

Practice 14 — Solution

void main() {
    String month = IO.readln().toLowerCase();
    String leap = IO.readln();
    String name = month.substring(0, 1).toUpperCase() + month.substring(1);
    if (month.equals("feb")) {
        if (leap.equals("yes")) {
            IO.println(name + " has 29 days");
        } else {
            IO.println(name + " has 28 days");
        }
    } else if (month.equals("apr") || month.equals("jun") || month.equals("sep") || month.equals("nov")) {
        IO.println(name + " has 30 days");
    } else if (month.equals("jan") || month.equals("mar") || month.equals("may") || month.equals("jul")
            || month.equals("aug") || month.equals("oct") || month.equals("dec")) {
        IO.println(name + " has 31 days");
    } else {
        IO.println("Unknown month");
    }
}

Lower-case first, then compare. Calling .toLowerCase() right after reading means "JUN", "Jun", and "jun" all match month.equals("jun"), and the display name can be built from that one clean copy.
