What Is an Expression?

Name the concept before diving into operators. An expression is any piece of code that the computer can evaluate to produce a single value. 3 + 4 is an expression. score * 2 is an expression. Even a lone literal like 42 is an expression. Expressions appear everywhere in programs — on the right side of an assignment, as arguments to IO.println, and later as conditions in if statements and loops. Once students see that distinction, every piece of syntax they encounter will feel more organized.

An expression is any combination of values, variables, and operators that the computer can evaluate to produce a single value.

Expression Evaluates to
3 + 4 7
10 - 3 7
score * 2 twice whatever score holds
100 100

Expressions appear everywhere in a program:

int total = price * quantity;   // expression on the right side
IO.println(score + 10);         // expression inside IO.println(...)

The computer evaluates the expression first, then uses the result.

Arithmetic Operators

Walk through each operator one at a time. Addition, subtraction, and multiplication are unsurprising — just flag that multiplication uses * not ×. Division is where things get interesting; hold the full explanation for the next slide. Modulo is the one students have never seen before — introduce the symbol and give the one-line definition, then hold examples for its own slide. The table is a reference; students should not try to memorize it on first pass.

Java has five arithmetic operators:

Operator Name Example Result
+ Addition 3 + 4 7
- Subtraction 10 - 3 7
* Multiplication 6 * 7 42
/ Division 10 / 4 2 ← watch out
% Modulo (remainder) 10 % 3 1

A quick note on each:

  • Multiplication is * — not × and not ·
  • Division with two whole numbers does not give a decimal — more on this next
  • Modulo (%) gives the remainder after division — more on this soon

Operator Precedence

PEMDAS from math class still applies in Java. Multiplication and division are evaluated before addition and subtraction. Within the same level, evaluation goes left to right. Parentheses override everything. Show a worked example where the answer changes depending on whether parentheses are present. The practical advice — when in doubt, add parentheses — is worth repeating. A program with extra parentheses is easier to read and less likely to have a subtle bug.

Java follows the same precedence rules as mathematics.

PEMDAS still applies:

  1. Parentheses first
  2. Multiplication and division (left to right)
  3. Addition and subtraction (left to right)

What does 2 + 3 * 4 evaluate to?

  2 + 3 * 4
= 2 + 12        ← multiplication first
= 14

Not 20. Multiplication happens before addition.

Parentheses override everything:

  (2 + 3) * 4
= 5 * 4         ← parentheses first
= 20

Tip

When in doubt — add parentheses. A program with extra parentheses is clearer and less likely to surprise you.

Integer Division

This is one of the most common surprises for beginners and it will bite them for weeks if they do not understand it clearly. When both operands are ints, Java performs integer division: the result is always a whole number and the decimal part is simply dropped — not rounded, just gone. 7 / 2 is 3, not 3.5, not 4. Show this with several examples. Then show how to get a decimal result: if either operand is a double, the division is decimal division. Make the connection back to types: it is the type of the operands that determines what kind of division happens.

Here is the most common surprise in this entire lecture:

int result = 7 / 2;
IO.println(result);    // prints 3, not 3.5

When both values are whole numbers, Java does integer division — the decimal part is dropped.

Expression Result Why
7 / 2 3 decimal part dropped
10 / 3 3 decimal part dropped
1 / 4 0 0.25 → drops to 0
8 / 2 4 divides evenly — no issue

Warning

The decimal part is dropped, not rounded. 7 / 2 gives 3, not 4.

To get a decimal result, make one of the values a decimal number:

double result = 7.0 / 2;    // one operand is a double → 3.5

The type of the operands determines the type of the result.

The Modulo Operator %

Modulo is the one operator most students haven’t seen before. The concept is simple — it is the remainder after division — but it takes a moment to click. Walk through the division-with-remainder picture: 7 divided by 2 goes 3 times with 1 left over. That leftover is what % gives you. Then show the practical uses, which are genuinely useful and will appear repeatedly throughout the course: checking even/odd, extracting the last digit of a number, wrapping around a fixed range.

% gives the remainder after integer division.

Think of it as division with leftovers:

7 ÷ 2 → goes 3 times, with 1 left over
7 % 2  →  1

More examples:

Expression Think Result
10 % 3 3 goes into 10 three times (9), leaving 1 1
15 % 5 5 goes into 15 exactly — no remainder 0
7 % 10 10 goes into 7 zero times, leaving 7 7

Practical uses you will see again and again:

// Is a number even or odd?
n % 2    // produces 0 if even, 1 if odd

// What is the last digit of a number?
n % 10   // extracts the ones digit

// Stay within a fixed range (e.g., hours on a clock)
hour % 24

Note

% only tells you the remainder — not how many times the division went. That is what / is for.

Integer.parseInt — Numbers from the User

IO.readln always produces a String — even if the user types 42, the program receives the text “42”, not the number 42. That distinction matters because you cannot do arithmetic on text. To convert “42” to the number 42, use Integer.parseInt. The syntax is straightforward: wrap the String in Integer.parseInt(…). Mention that if the user types something that is not a valid number — like “hello” — the program will crash. Handling that gracefully is a topic for later in the course.

IO.readln always produces a String — even if the user types a number.

String input = IO.readln("How many minutes? ");
// input holds "137" — the TEXT, not the number

You cannot do arithmetic on a String:

input / 60    // ERROR — can't divide text

Integer.parseInt converts a String to an int:

int minutes = Integer.parseInt(input);
// now minutes holds the number 137

Or in one step:

int minutes = Integer.parseInt(IO.readln("How many minutes? "));

Warning

If the user types something that is not a whole number — like "hello" or "3.5" — the program will crash. Handling that gracefully is a topic for later in the course.

String Concatenation

This is the formal introduction of string concatenation, deferred from the variables deck. The + operator does two different things depending on the types involved. int + int is arithmetic. String + anything is concatenation — the values are joined into a single String. The anything part is important: Java automatically converts a number to its text form before joining. Show the clean cases first, then the surprising mixed case. The left-to-right evaluation rule is the key to understanding “5” + 3 + 4 = “534” vs 5 + 3 + “4” = “84”. Connect back to deck 02: we printed labels and values on separate lines because we did not have concatenation yet — now we can put them on the same line.

The + operator does different things depending on the types involved.

With two numbers — addition:

int a = 5;
int b = 3;
IO.println(a + b);     // prints: 8

With a String — concatenation (joining):

String first = "Hello, ";
String second = "world!";
IO.println(first + second);    // prints: Hello, world!

Mixing a String and a number:

int score = 42;
IO.println("Score: " + score);   // prints: Score: 42

Java converts the number to text automatically before joining.

Watch out — order matters:

IO.println("Total: " + 5 + 3);   // prints: Total: 53  ← not 8!
IO.println("Total: " + (5 + 3)); // prints: Total: 8   ← add first

Evaluation goes left to right: "Total: " + 5 produces "Total: 5", then "Total: 5" + 3 produces "Total: 53".

Tip

Recall from last lecture: we printed labels and values on separate lines because we did not have + yet. Now we can write IO.println("Score: " + score) and put them on one line.

Common Mistakes

Four mistakes that will appear in student code in the first few weeks. Integer division truncation is the most common — stress it again. The concatenation surprise (mixing + with Strings and numbers in unexpected ways) is the most confusing. Make sure students leave knowing these pitfalls by name so they can recognize them when they appear.

1. Expecting a decimal from integer division

int result = 7 / 2;
IO.println(result);    // prints 3 — not 3.5

Fix: make one operand a decimal — 7.0 / 2.

2. Missing parentheses changing the result

int avg = 10 + 20 / 2;   // prints 20 — not 15
int avg = (10 + 20) / 2; // prints 15 — as intended

3. The concatenation surprise

IO.println("Answer: " + 2 + 3);   // prints: Answer: 23
IO.println("Answer: " + (2 + 3)); // prints: Answer: 5

Once a String is involved, + becomes concatenation — not addition.

4. Forgetting Integer.parseInt

String input = IO.readln("Enter a number: ");
IO.println(input * 2);   // ERROR — can't multiply a String

Fix: int n = Integer.parseInt(input);
