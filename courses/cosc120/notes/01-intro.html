What Is a Computer?

Brief and grounded — just enough to set up the “everything is a computer” point later. Hit the three parts: CPU executes instructions, RAM is fast scratch-pad memory that vanishes when power goes off, storage is where things persist. The goal is not a hardware lecture — it’s to plant the idea that a computer is a machine that executes instructions, and that a phone is also a machine that executes instructions.

A computer is a machine built around three things:

Part What it does
CPU The brain — fetches and executes instructions, billions per second
Memory (RAM) The scratch pad — fast, but gone when the power goes off
Storage The filing cabinet — slow, but permanent

Everything else — keyboard, screen, WiFi — is just input and output.

Your Phone Is Also a Computer

Students relate to phones far more than to desktop PCs. The key insight: a phone has a CPU, RAM, and storage — it IS a computer. The difference is that phone manufacturers have wrapped everything in a layer of apps and made it very hard to program the device directly. But every single app was written by a programmer. This sets up the “using vs. programming” distinction on the next slide.

Under the hood, your phone has a CPU, RAM, and storage.

It is a computer — manufacturers just hide the machinery behind apps.

Think about every app on your phone:

  • The alarm app
  • The maps app
  • The game you play on the bus
  • The on-screen keyboard

Your Phone Is Also a Computer

Every one of these was written by a programmer who sat down and wrote instructions, one line at a time.

That is what you are learning to do.

Two Ways to Use a Computer

This is the conceptual heart of the first lecture. Spend time here. When you “use” a computer you’re running someone else’s program. When you “program” a computer you are the one writing the instructions the machine will follow. The second path is harder but it’s also what gives you real power over the machine.

Two Ways to Use a Computer

Using a Computer

  • Open an app → it runs
  • Click a button → something happens
  • Someone else wrote those instructions
  • You follow the rules someone else set

Programming a Computer

  • You write the instructions
  • The computer does exactly what you say
  • You set the rules
  • (Whether or not that’s what you meant is another story)

Most people use computers. This course teaches you to program them.

What Is a Program?

Introduce the recipe analogy here — it’s intuitive and you’ll return to it. A recipe is a list of precise, ordered steps that a cook follows. A program is exactly that, but for a CPU instead of a cook. Key word: PRECISE. “Add salt to taste” would be a bug.

A program is a precise, ordered sequence of instructions for a computer.

The best analogy: a recipe.

Recipe Program
Ingredients Data — numbers, text, …
Steps Instructions
Cook CPU
Finished dish Output

A recipe tells a cook exactly what to do. A program tells a CPU exactly what to do.

Programming Is Like Mailing a Recipe

This is the key insight about completeness and unambiguity. When you cook yourself you can improvise. When you mail the recipe to a stranger, every step must be spelled out — they can’t call you mid-bake. A program is a mailed recipe: the computer follows it exactly with no improvisation and no common sense. If a step is missing or ambiguous, it either fails or does something wrong.

Imagine you’re cooking something following a recipe:

  • Something unclear? Improvise. Ask a friend. Use judgment.

Now imagine giving that recipe to a friend who is going camping for a few days and has no internet or phone:

  • They follow only what is written
  • They cannot call you mid-cook
  • “Add salt to taste” → useless. How much?
  • Every step must be complete and unambiguous

Programs as recipes

A program is a recipe - the computer opens the envelope and follows the instructions exactly.

No improvising, no common sense, no filling in gaps.

Why Can’t Computers Just Understand English?

Natural language is wonderfully ambiguous — that’s a feature for poetry and conversation, and a serious bug for programming. We invented programming languages precisely to eliminate ambiguity. This is why programs look the way they do: strange syntax, strict rules, no shortcuts. Every quirk of a programming language exists to make sure there is exactly one valid reading of every statement.

English is beautifully ambiguous:

“I saw a man on a hill with a telescope.”

Why Can’t Computers Just Understand English?

Humans resolve ambiguity with context, tone, and common sense.

Computers have none of these.

Programming languages are designed so every statement has exactly one meaning.

That is why they look the way they do — no shortcuts, no “you know what I mean.”

Learning a New Language

Programming IS like learning a new language — make this connection explicit. The vocabulary is small compared to French or Spanish, but the grammar is absolute: no partial credit, no “close enough”, no context to save you from a typo. The good news is the vocabulary is tiny. The bad news is every rule is enforced by a machine that has no sympathy. Emphasize that this takes practice, not just reading.

Programming is genuinely like learning a new language:

  • Vocabulary: small — a few dozen keywords in Java
  • Grammar: absolute — one wrong character breaks everything
  • Accent: none allowed — spelling, capitalization, and punctuation are all exact

But like any language, you don’t learn it by reading about it.

You learn it by using it — making mistakes, getting confused, and practicing until it clicks.

Important

The in-class worksheets and homework are not optional extras. They are the practice reps. You cannot get fluent by watching someone else do it.

What About AI?

Students are thinking about this already — address it directly and honestly. AI tools like ChatGPT and GitHub Copilot can write Java code, often impressively well. Don’t dismiss this. Be honest. Then give the real reason it’s not allowed: you’re here to build understanding and skill. If AI does the reps for you, you don’t build anything — and in an exam, on a job, when something breaks at 2am, you’re on your own. The calculator analogy is strong: you learned arithmetic before you were allowed to use a calculator, not because arithmetic is more important than calculators, but because you needed to understand what the calculator was doing.

Yes — AI tools can write code. Sometimes very well.

So why aren’t you allowed to use them in this course?

The same reason you learned long division before using a calculator:

Understanding why the code works is what makes you a programmer.

AI can hand you a correct answer without you understanding a thing. That works great — until:

  • You need to modify the code
  • Something breaks and you have to debug it
  • You sit down for an exam

AI use on assignments and tests is not allowed. This is not because AI is bad — it is a powerful tool you will likely use in your career. But right now, you need to build the skills. The reps matter.

Your First Java Program

Use the modern Java 25 flexible-main syntax: void main() with no public static. IO.println is the course’s simplified output wrapper — no System.out.println boilerplate. Walk through each piece of the program carefully: void main() means “start here”, curly braces wrap a block of code, IO.println prints a line, the string is in double quotes, and the semicolon ends the statement like a period ends a sentence. Do NOT spend time on the compile/run cycle — students use an online IDE where that is invisible.

void main() {
    IO.println("Hello, World!");
}

Every piece has a job:

Piece What it means
void main() “Start here when the program runs”
{ } Curly braces wrap a block of code
IO.println(...) Print a line to the screen
"Hello, World!" The text to print — always in double quotes
; End of statement (like a period at the end of a sentence)

What the Computer “Hears”

Lighten the mood — this is intentionally humorous. The underlying point is serious: the computer is completely literal. It has no intuition about what you “meant.” This slide sets up the importance of exact syntax, matched braces, and semicolons. Use it to open a conversation: what happens if the semicolon is missing? What if you write Println instead of println?

// What you type:                   // What the computer hears:
void main() {                       // "Dear Computer,"
    IO.println("Hello");            // "Please print 'Hello' on the screen."
}                                   // "Thanks and regards, Programmer"

The computer is completely literal. It does precisely what you wrote.

Miss a semicolon — error. Write Println instead of println — error. Forget a closing brace — error.

Programming feels hard at first because you are learning to think like someone with no common sense whatsoever.

That gets easier with practice. Promise.

Whitespace and Readability

Students often wonder if indentation “counts.” Honest answer: the compiler ignores whitespace almost entirely. But humans don’t — and your code will be read by humans (you, a classmate, your professor, a TA, eventually an employer). Readable code is professional code. Also: when your program has a bug, readable code is much easier to debug. Establish the expectation early: indentation is required in this course.

These two programs are identical to the computer:

void main() {
    IO.println("Hello");
    IO.println("World");
}

Readable

void main(){IO.println("Hello");IO.println("World");}

Valid, but painful

The computer does not care. You should.

  • Indentation reveals structure at a glance
  • Blank lines separate ideas
  • Consistent style makes bugs easier to find

Tip

In this course, indentation is required. Write readable code from day one — your future self will thank you.

Comments — Notes for Humans

Comments are text inside code that the computer ignores completely. They exist purely for the human reader — yourself, a classmate, your professor. Introduce both the concept and the syntax: // makes everything after it on that line a comment. Then talk specifically about how comments will be used in this course: homework assignments will ask students to explain their thinking in comments, and the grader reads them. This is also a good time to distinguish a useful comment from a useless one — “prints hello” adds nothing; “converts the raw score to a letter grade” actually helps.

A comment is a note you write inside your code.

The computer ignores it completely. It is there for the human reading the code.

void main() {
    // This program greets the user.
    IO.println("Hello, World!");   // prints a greeting to the screen
}

Everything after // on a line is a comment — it has no effect on what the program does.

Why write comments?

  • To explain what a piece of code is doing
  • To explain why you made a particular choice
  • To leave a note for yourself when you come back to the code later
  • To communicate with your professor and grader

In this course, many assignments will ask you to explain your reasoning in comments. The grader reads them. A correct program with no comments is less valuable than one that shows you understood what you were doing.

A good comment explains intent — not just what the code says:

// BAD — just repeats what the code already says
IO.println("Hello");   // prints Hello

// GOOD — explains why this line is here
IO.println("Hello");   // greeting displayed before asking for the user's name

Tip

Java also has multi-line comments: /* anything here */. We will mostly use // — one line at a time is clearer and easier to maintain.

IO.println — Printing to the Screen

IO.println is the course wrapper for output. Each call prints one line of text and moves the cursor to the next line. You can print strings (in double quotes) or numbers (no quotes). Crucially: the ORDER of calls determines the order of output. This sets up the top-to-bottom execution slide.

IO.println prints one line and moves to the next.

void main() {
    IO.println("Apples");
    IO.println("Bananas");
    IO.println("Cherries");
}

Output:

Apples
Bananas
Cherries

IO.println — Printing to the Screen

You can also print numbers directly — no quotes needed:

void main() {
    IO.println(42);
    IO.println(3.14);
}

Output:

42
3.14

Programs Execute Top to Bottom

Sequential execution is the default model. The computer runs statements in order, one at a time, from top to bottom — exactly like reading a recipe. Nothing runs out of order; nothing is skipped unless you tell it to (conditionals, loops — coming later). Trace this program together as a class before moving on.

Java executes statements in order — one at a time, top to bottom.

void main() {
    IO.println("First");
    IO.println("Second");
    IO.println("Third");
}

The computer runs line 2, then line 3, then line 4. Always, in that order.

Note

Later in this course, we will learn to make programs jump (conditionals), repeat (loops), and call other code (methods). But the default is always: one step at a time, top to bottom, just like following a recipe.
