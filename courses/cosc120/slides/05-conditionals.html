Programs Don’t Always Go Straight

Every program written so far runs the same way every time: top to bottom, one line after another, no detours. That is a straight line. But real useful programs need to make decisions — do this in one situation, do something else in another. That is a branch. The visual of a straight line versus a Y-shaped split is the central image of this lecture. The humor slide is the hook: students already know “If you are happy and you know it, clap your hands.” Java says the same thing. Show the Java version first for laughs, then use it to introduce the real syntax.

Every program we have written so far does the same thing every run — top to bottom, no detours.

But most programs need to make decisions.

You already know how this works. You have known since kindergarten:

“If you’re happy and you know it, clap your hands.”

In Java:

void main() {
    String mood = IO.readln("Are you happy? (yes/no) ");
    if (mood.equals("yes")) {
        IO.println("Clap your hands!");
        IO.println("(stomp your feet — coming in a future lecture)");
    }
}

The IO.println inside only runs if the condition is true. That is a conditional.

Conditionals in Everyday English

Before showing any more Java syntax, ground the idea in language students already use. Conditionals are not a computer science invention — they are a feature of every human language. We navigate our entire lives using if/else logic. Java just requires us to be more precise about it: the condition must be something that is either true or false, and the body must be inside braces. Show the English-to-Java translation side by side. This makes the syntax feel like a formality rather than something alien.

We use conditionals constantly — in language, in decisions, in instructions.

In English:

  • If it is raining, take an umbrella.
  • If the light is red, stop.
  • If you are hungry, eat something.
  • If the tank is empty, get gas.

The structure is always the same:

if [some condition is true]
    then do [something]

Java uses the same structure — just written more precisely:

if (condition) {
    // do something
}

The condition must be something that is either true or false — nothing in between.

The code inside the braces only runs when the condition is true. Otherwise, it is skipped entirely.

Relational Operators

Relational operators produce a boolean — true or false. Students have seen these symbols in math class; the only ones that look different are == (equality, not assignment) and != (not equal). Spend a moment on == vs = — this is the most common mistake in this entire unit. In math, = means equality. In Java, = means assignment and == means equality. They are completely different. Mention this now, and it will appear again in common mistakes.

A condition is built from a relational operator — a comparison that produces true or false.

Operator Meaning Example Result
< less than 3 < 5 true
> greater than 3 > 5 false
<= less than or equal to 5 <= 5 true
>= greater than or equal to 6 >= 10 false
== equal to 4 == 4 true
!= not equal to 4 != 5 true

A few things worth noting:

  • == is two equals signs — it checks equality
  • = is one equals sign — it stores a value (assignment). These are completely different.
  • <= and >= are written with the < or > first, then = — not the other way around
int score = 85;
IO.println(score > 60);    // true
IO.println(score == 100);  // false
IO.println(score != 85);   // false
IO.println(score >= 85);   // true

The if Statement

Walk through the syntax carefully: the keyword if, the condition in parentheses, the body in braces. The body is the code that only runs when the condition is true. When the condition is false, the entire body is skipped and execution continues with whatever comes after the closing brace. Use the figure to make the two possible paths concrete. The indentation inside the braces is convention — Java does not require it, but every professional programmer uses it because it makes the structure visible at a glance.

if (condition) {
    // this code only runs when the condition is true
}

The pieces:

  • if — the keyword
  • (condition) — something that is true or false, in parentheses
  • { } — the body: the code that runs when the condition is true

Example:

int score = 72;

if (score >= 60) {
    IO.println("You passed.");
}

IO.println("Done.");

When score is 72: - 72 >= 60 is true - "You passed." is printed - "Done." is printed

When score is 45: - 45 >= 60 is false - The body is skipped entirely - "Done." is still printed

The if/else Statement

With a plain if, the body either runs or is skipped. With if/else, exactly one of the two branches always runs — never both, never neither. The else branch is the default: it runs when the condition is false. The figure here is the classic Y-split: the program arrives at a fork, takes one path or the other, and both paths lead to the same place afterward. Stress “exactly one” — this is different from two separate if statements, which could both run or both be skipped.

Sometimes you want to do one thing if a condition is true, and something different if it is false.

if (condition) {
    // runs when condition is true
} else {
    // runs when condition is false
}

Exactly one branch always runs — never both, never neither.

int score = 45;

if (score >= 60) {
    IO.println("You passed.");
} else {
    IO.println("You did not pass.");
}

When score is 72 → prints "You passed." When score is 45 → prints "You did not pass."

Note

Two separate if statements are not the same as if/else. With two if statements, both conditions are checked independently and both bodies could run. With if/else, only one branch runs.

Tracing a Conditional

Tracing means following exactly what the computer does, step by step. The key habit to build: before running the program, ask “what will the condition evaluate to for this input?” That tells you which branch runs. Show both scenarios and ask students to predict before revealing. The figure — two colored paths through the same flowchart shape — makes the two possible executions concrete without needing a dense table.

void main() {
    int temperature = Integer.parseInt(IO.readln("Temperature (°F): "));

    if (temperature >= 70) {
        IO.println("It is warm outside.");
    } else {
        IO.println("It is cold outside.");
    }

    IO.println("Have a nice day.");
}

User types 85

85 >= 70 → true

✓ runs: “It is warm outside.” ✗ skips: else branch

→ “Have a nice day.”

User types 50

50 >= 70 → false

✗ skips: if branch ✓ runs: “It is cold outside.”

→ “Have a nice day.”

Comparing Strings — .equals()

This is one of the most important things to get right before students write any programs that read String input. == on Strings does not check whether they have the same content — it checks whether they are literally the same object in memory. For beginners, this distinction does not need to be explained deeply; just give the rule and the reason why: for Strings, always use .equals(). Show the bug that == produces and why .equals() fixes it. The sticky note analogy works well: == asks “are these the same sticky note?” (same physical piece of paper); .equals() asks “do these sticky notes say the same thing?” Students comparing user input to a String literal must always use .equals().

You know that == compares two values. For numbers, this works perfectly:

int score = 85;
IO.println(score == 85);   // true ✓

For Strings, == does not work the way you expect:

String answer = IO.readln("Type yes: ");

if (answer == "yes") {          // ✗ — this may not work!
    IO.println("You said yes.");
}

Even if the user types yes, this condition may be false.

The rule: always use .equals() to compare Strings.

String answer = IO.readln("Type yes: ");

if (answer.equals("yes")) {     // ✓ — this always works
    IO.println("You said yes.");
}

Think of it like two sticky notes that both say "yes". == asks “are these physically the same sticky note?” — almost never what you want. .equals() asks “do they say the same thing?” — which is what you actually care about.

The full explanation for why == behaves this way on Strings is coming later in the course. For now, just remember the rule.

Warning

For String comparison, always use .equals() — never ==. We will explain exactly why later in the course.

Code Example — Is It Warm Enough?

A complete program that uses if/else, a relational operator, and String comparison — all in one. Walk through the flowchart, then the code, then trace through with two inputs. The program asks for a temperature and whether the person wants to go outside, then gives advice. Keep the logic simple — this deck only covers plain if/else, not boolean logic or else if.

Problem: Ask the user for the current temperature. If it is 65°F or above, tell them it is a good day to go outside. Otherwise, suggest they stay in.

void main() {
    int temperature = Integer.parseInt(IO.readln("Current temperature (°F): "));

Common Mistakes

Three mistakes that will show up in almost every student’s code this week. The = vs == mistake is the most frequent and the hardest to spot because the program compiles — it just does the wrong thing. Missing braces is dangerous because removing braces from a multi-line body silently changes which lines are inside the if. Using == on Strings compiles and runs but produces wrong results with user input. Go through each one slowly.

1. Using = instead of == in a condition

int score = 85;
if (score = 100) {    // ERROR — this is assignment, not comparison
    IO.println("Perfect score!");
}

= stores a value. == compares values. In a condition, you always want ==.

2. Missing braces — only the first line is inside the if

if (score >= 60)
    IO.println("Passing");
    IO.println("Congratulations");   // always runs — NOT inside the if

Without braces, only the very next line is inside the if. Always use braces.

if (score >= 60) {
    IO.println("Passing");
    IO.println("Congratulations");   // now both lines are inside the if ✓
}

3. Using == to compare Strings

String name = IO.readln("Your name: ");
if (name == "Alice") {      // ✗ — may always be false
    IO.println("Hello, Alice!");
}
if (name.equals("Alice")) { // ✓ — compares the content
    IO.println("Hello, Alice!");
}
