Strings

Learning Outcomes

  • Use .length(), .charAt(), .substring(), .toUpperCase(), and .toLowerCase() to work with String values

What Is a String?

Students have been using Strings since week one — now they learn what is actually inside one. A String is a sequence of characters, stored in order, with each character at a numbered position starting from zero. The zero-based indexing is the key new idea here and it will come back in arrays. Use a concrete word — “Alice” — and show the index box diagram. Make sure students absorb: the LAST index is always length minus one, never length itself.

A String is a sequence of characters stored in order.

Each character sits at a numbered position, called its index.

Indexes start at zero — not one.

String name = "Alice";
Index 0 1 2 3 4
Character A l i c e
  • First character: index 0
  • Last character: index 4 (which is length 5 minus 1)

Warning

The last valid index is always length - 1, never length itself. Asking for index 5 on "Alice" is an error.

Asking a String Things — The Dot

This is the key conceptual slide before any specific operations. Students have already seen .equals() on Strings — so they have encountered the dot before, but without explanation. Now explain it: when you put a dot after a String variable, you can ask that String to tell you something about itself or give you a transformed version. Each operation is written as variable.operationName(…). The parentheses are required even if there is nothing inside them. This framing — “asking the String something” — avoids the word method and is genuinely intuitive.

You already know how to do things with numbers: score + 10, total / count.

Strings work differently. To do something with a String, you write:

variableName.whatYouWantToDo(...)

The dot connects the String to the operation you want to perform.

String name = "Alice";

name.length()          // ask: how many characters are you?
name.charAt(0)         // ask: what is your character at index 0?
name.toUpperCase()     // ask: can you give me an uppercase version?
name.substring(1, 3)   // ask: can you give me characters 1 through 2?

Think of it as asking a question directly to the String value.

The String produces an answer — a new value you can store, print, or use.

Note

The parentheses () are always required, even when you are not putting anything inside them. You will see why this matters more when we cover methods later in the course.

.length()

.length() produces the number of characters in the String, including spaces and punctuation. Walk through several examples. The most common mistake: using .length() as an index (off by one — the last index is length - 1). Show this as a warning. Good practice: use .length() in expressions, like checking if a String is empty (length == 0) or too long (length > 20).

.length() asks the String how many characters it contains.

String name  = "Alice";
String city  = "Baltimore";
String empty = "";
String space = "Hello World";

IO.println(name.length());    // 5
IO.println(city.length());    // 9
IO.println(empty.length());   // 0
IO.println(space.length());   // 11  (the space counts!)

You can use the result in expressions:

String password = IO.readln("Enter password: ");

if (password.length() < 8) {
    IO.println("Password is too short.");
} else {
    IO.println("Password length is OK.");
}

Warning

name.length() is 5 for "Alice". The last valid index is 4 — not 5. name.charAt(name.length()) is an error.

.charAt()

.charAt(i) produces the character at index i. This introduces char — a new type students haven’t seen. Keep it brief: a char holds exactly one character, written in single quotes. The main use of charAt for beginners: get the first character (charAt(0)), get the last character (charAt(length - 1)), check what a String starts with. Make sure students practice the zero-based index by asking them to predict charAt(0), charAt(1), etc. for a given String before showing the answers.

.charAt(i) asks the String for its character at index i.

String word = "Hello";

IO.println(word.charAt(0));   // H
IO.println(word.charAt(1));   // e
IO.println(word.charAt(4));   // o  (last character)

The result is a single character. In Java, a single character has its own type: char.

char first = word.charAt(0);   // first holds 'H'
IO.println(first);             // H

Note: char values are written in single quotes ' ' — not double quotes " ".

Common uses:

String name = IO.readln("Enter your name: ");

// Get the first letter
char initial = name.charAt(0);
IO.println("Your initial is: " + initial);

// Get the last letter
char last = name.charAt(name.length() - 1);
IO.println("Last character: " + last);

Warning

word.charAt(word.length()) is always an error — index out of bounds. The last valid index is word.length() - 1.

.substring()

.substring() extracts a portion of a String. It has two forms: one argument (from start to end) and two arguments (from start, up to but not including end). The “end is exclusive” rule is the hardest part — stress it with examples. The diagram showing the slice with start included and end excluded is essential. Analogy: substring(1, 4) means “start at 1, stop just before 4” — like a half-open interval in math.

.substring() asks the String for a piece of itself.

One argument — from that index to the end:

String word = "Hello";
IO.println(word.substring(2));    // "llo"  (from index 2 to the end)
IO.println(word.substring(0));    // "Hello" (the whole thing)

Two arguments — from start up to (but not including) end:

String word = "Hello";
IO.println(word.substring(1, 4));   // "ell"  (indexes 1, 2, 3 — not 4)
IO.println(word.substring(0, 3));   // "Hel"  (indexes 0, 1, 2 — not 3)

Warning

The second argument is exclusive — the character at that index is not included.

substring(1, 4) gives you indexes 1, 2, 3 — not 4.

Practical example — extract a first name from “Alice Smith”:

String full = "Alice Smith";
int spacePos = 5;                        // the space is at index 5
String firstName = full.substring(0, spacePos);    // "Alice"
String lastName  = full.substring(spacePos + 1);   // "Smith"
IO.println(firstName);
IO.println(lastName);

.toUpperCase() and .toLowerCase()

These produce a new String with all characters converted. They do not affect the original. This is a preview of immutability (covered next slide). Show both directions, show that the original is unchanged, show that you must store the result to use it. Good practical use: normalizing user input for comparison — convert to lowercase before using .equals() so the comparison is case-insensitive.

.toUpperCase() produces an all-uppercase version of the String. .toLowerCase() produces an all-lowercase version.

String name = "Alice";

IO.println(name.toUpperCase());   // ALICE
IO.println(name.toLowerCase());   // alice
IO.println(name);                 // Alice  ← unchanged!

The original String is not affected — you get a new value back.

To use the result, store it:

String name  = "Alice";
String upper = name.toUpperCase();   // store the result

IO.println(upper);   // ALICE
IO.println(name);    // Alice — still the original

Practical use — case-insensitive comparison:

String answer = IO.readln("Continue? (yes/no) ");

// Works whether user types "yes", "Yes", "YES", "YES", ...
if (answer.toLowerCase().equals("yes")) {
    IO.println("Continuing...");
}

Strings Are Immutable

Immutable means cannot be changed. Once a String is created, its characters are fixed — no operation changes it. Every String operation produces a NEW String. This is the most common source of bugs in this unit: students write name.toUpperCase() and then wonder why name is still lowercase. Because they did not store the result. The photocopy analogy works well: toUpperCase() makes a photocopy in uppercase — it does not alter the original.

Immutable means: once created, a String cannot be changed.

Every operation on a String produces a new String — it never alters the original.

String name = "alice";
name.toUpperCase();        // produces "ALICE" — but where did it go?

IO.println(name);          // alice — name is still lowercase

name.toUpperCase() produced a value. But we did not store it anywhere, so it was immediately discarded.

The fix — store the result:

String name  = "alice";
String upper = name.toUpperCase();   // store the new String

IO.println(name);    // alice  — original unchanged
IO.println(upper);   // ALICE  — the new one

Warning

String operations do not change the original. If you want to keep the result, you must store it in a variable.

Chaining String Operations

Chaining means applying one operation to the result of another, in a single expression. The key insight: since each operation produces a new String, you can immediately apply another operation to that new String. Walk through the evaluation left to right. The most common use: lowercase before comparing (case-insensitive check). Or get the first character uppercased. Keep examples to two operations chained — more than two becomes hard to read.

Since each String operation produces a new String, you can immediately ask that new String another question.

String name = "alice smith";

// One at a time:
String upper = name.toUpperCase();      // "ALICE SMITH"
char first   = upper.charAt(0);        // 'A'

// Chained into one expression:
char first = name.toUpperCase().charAt(0);   // 'A'

The evaluation goes left to right:

name.toUpperCase().charAt(0)
      ↓
"ALICE SMITH".charAt(0)
      ↓
'A'

More examples:

String word = "Hello, World!";

// First 5 characters, lowercased:
IO.println(word.substring(0, 5).toLowerCase());   // hello

// Length of an uppercased version (same as original length):
IO.println(word.toUpperCase().length());           // 13

Tip

Chaining is convenient, but keep it to two operations at most in a single expression. Three or more chained together becomes hard to read and hard to debug.

Comparing Strings — .equals() Revisited

Students saw this in the conditionals lecture. Now revisit it in the context of everything they have learned about Strings. The rule is unchanged: always use .equals(), never ==. Add one practical extension: case-insensitive comparison using .equalsIgnoreCase(), which is cleaner than lowercasing first. Also add: comparing a String variable to a literal — some instructors put the literal first (“yes”.equals(answer)) to avoid a crash if answer is null, but at this stage that is too much to introduce. Keep it simple: variable.equals(“literal”).

We covered this in the conditionals lecture. A quick review plus one new tool:

Always use .equals() — never == — to compare Strings:

String answer = IO.readln("Type yes: ");

if (answer == "yes") {           // ✗ — unreliable
    IO.println("You said yes.");
}

if (answer.equals("yes")) {      // ✓ — always correct
    IO.println("You said yes.");
}

New: .equalsIgnoreCase() — compares without caring about case:

String answer = IO.readln("Continue? (yes/no) ");

// Accepts "yes", "Yes", "YES", "YeS", ...
if (answer.equalsIgnoreCase("yes")) {
    IO.println("Continuing...");
}

This is cleaner than writing answer.toLowerCase().equals("yes") and does the same thing.

Warning

== does not compare String content reliably. The full explanation is coming later in the course. For now: always use .equals() or .equalsIgnoreCase().

Code Example — Format a Name

A complete program that uses charAt, length, substring, toUpperCase, and equals together. Ask the user for a first and last name, then print: the initials, the full name in uppercase, and the total character count. Walk through each line. This is also a good chance to show chaining — name.toUpperCase() in IO.println directly.

Problem: Ask the user for their first name and last name. Print their initials, their full name in uppercase, and the total number of characters in both names combined.

void main() {
    String first = IO.readln("First name: ");
    String last  = IO.readln("Last name: ");

    // Initials — first character of each name
    char firstInitial = first.charAt(0);
    char lastInitial  = last.charAt(0);

    IO.println("Initials: " + firstInitial + "." + lastInitial + ".");

    // Uppercase versions
    IO.println("Uppercase: " + first.toUpperCase() + " " + last.toUpperCase());

    // Total characters (not counting the space between names)
    int total = first.length() + last.length();
    IO.println("Total characters: " + total);
}

Sample run:

First name: Alice
Last name: Smith
Initials: A.S.
Uppercase: ALICE SMITH
Total characters: 10

Common Mistakes

Four mistakes that will appear constantly this week. The first two — not storing the result, and using == — are the most damaging because they produce no compile error, just wrong behavior. Off-by-one in substring is a close third.

1. Forgetting to store the result of a String operation

String name = "alice";
name.toUpperCase();         // result is produced and immediately discarded
IO.println(name);           // still "alice" — nothing changed

String upper = name.toUpperCase();   // ✓ — store it
IO.println(upper);          // ALICE

2. Using == instead of .equals()

String color = IO.readln("Favorite color: ");
if (color == "blue") { ... }          // ✗ — unreliable
if (color.equals("blue")) { ... }     // ✓

3. Off-by-one in .substring()

String word = "Hello";
IO.println(word.substring(1, 4));   // "ell" — indexes 1, 2, 3
IO.println(word.substring(1, 5));   // "ello" — indexes 1, 2, 3, 4
// The second argument is the first index NOT included

4. Using .length() as an index

String name = "Alice";           // length is 5
char last = name.charAt(5);      // ERROR — index 5 does not exist
char last = name.charAt(name.length() - 1);   // ✓ — index 4
