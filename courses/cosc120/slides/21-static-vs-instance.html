static vs Instance

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Write a static method — declared with static, taking only parameters (no access to instance fields) — and call it with ClassName.method(args)
  • Write a static field — declared with static — and explain that all objects of the class share the same copy
  • Distinguish static members (belong to the class) from instance members (belong to each object) in a class definition
  • Decide whether a method or field should be static or instance for a given design problem
  • Write a class that combines static and instance members and call each correctly from main

You Have Already Used Static Methods

You have been calling static methods since day one:

Integer.parseInt("42")     // static — called on Integer, not on an object
Math.abs(-5)               // static — called on Math
Math.max(3, 7)             // static — called on Math

Notice: no new Integer() or new Math() first. You call directly on the class name.

That is the signature of a static member — it belongs to the class itself, not to any specific object.

Callback to familiar code. Students have been calling Integer.parseInt() since they first read user input, and Math.abs() when they needed absolute value. They never wondered why there’s no “new Integer()” — now they find out. The class name before the dot, rather than an object variable, is the tell.

What Does static Mean?

Instance member Static member
Belongs to Each individual object The class itself
How many copies One per object Exactly one, shared by all
How to call/access object.method() or object.field ClassName.method() or ClassName.field
Knows this? Yes No — there is no “this” object

One-line rule: if the method or field doesn’t need to know which object it’s working with, make it static.

The table is the core reference — come back to it. The “no this” rule is the practical guide: if you tried to write a static method that accessed name or grade (instance fields), the compiler would refuse with “non-static field cannot be referenced from a static context.” Static methods only know about their parameters and other static fields.

Static Methods

A static method inside a class is a utility function — it does work based purely on its parameters, not on any object’s state:

class MathUtils {
    static int square(int n) {
        return n * n;
    }

    static boolean isEven(int n) {
        return n % 2 == 0;
    }

    static int clamp(int value, int min, int max) {
        if (value < min) { return min; }
        if (value > max) { return max; }
        return value;
    }
}

Called on the class name:

IO.println(MathUtils.square(7));          // 49
IO.println(MathUtils.isEven(4));          // true
IO.println(MathUtils.clamp(150, 0, 100)); // 100

MathUtils has no fields — it’s just a container of related utility functions. square(7) doesn’t need to know about any object; it only needs the number 7. This is exactly why Math.abs() is static in Java’s standard library: it’s a pure calculation with no object state involved. The calling syntax ClassName.method() makes the “no object needed” explicit.

Writing a Static Method

Add the keyword static before the return type:

class Student {
    String name;
    int grade;

    Student(String name, int grade) {
        this.name  = name;
        this.grade = grade;
    }

    // Instance method — knows which student
    String letterGrade() {
        return gradeToLetter(grade);    // calls the static helper
    }

    // Static helper — pure calculation, no object needed
    static String gradeToLetter(int g) {
        if (g >= 90) { return "A"; }
        if (g >= 80) { return "B"; }
        if (g >= 70) { return "C"; }
        if (g >= 60) { return "D"; }
        return "F";
    }
}
IO.println(Student.gradeToLetter(85));    // B — called on class
IO.println(alice.letterGrade());          // B — called on object

This pattern is common: an instance method delegates a calculation to a static helper because the math itself has nothing to do with a specific student. gradeToLetter() takes a plain int — it works for any grade, not just a Student’s. Note that the instance method CAN call the static method (it just calls gradeToLetter(grade)); the reverse is not allowed (a static method cannot call an instance method without specifying an object).

Static Fields

A static field is a variable that all objects of the class share — one copy, period:

class Student {
    static int totalCreated = 0;    // shared by ALL students
    String name;
    int grade;

    Student(String name, int grade) {
        this.name  = name;
        this.grade = grade;
        totalCreated = totalCreated + 1;   // increment EVERY time a new student is made
    }
}
Student alice = new Student("Alice", 88);
Student bob   = new Student("Bob",   74);
Student carol = new Student("Carol", 91);

IO.println(Student.totalCreated);   // 3

totalCreated is not inside any one student — it’s attached to the class. Every time the constructor runs (every time new Student(…) is called), it increments the same shared counter. After creating alice, bob, and carol, totalCreated is 3 regardless of which student variable you check through. Access via ClassName.field (Student.totalCreated) makes it clear this is class-level data.

Static Constants

The most common use of static fields is constants — values that never change:

class Circle {
    static double PI = 3.14159265;   // shared constant

    double radius;

    Circle(double radius) {
        this.radius = radius;
    }

    double area() {
        return PI * radius * radius;  // uses the shared constant
    }
}

Java’s standard library uses this pattern everywhere: - Integer.MIN_VALUE — smallest possible int - Integer.MAX_VALUE — largest possible int - Math.PI — π to 15 decimal places

Constants are the cleanest use of static fields: there’s one value of PI no matter how many circles exist. The instance method area() can reference PI because it’s in the same class — no ClassName. prefix needed from inside the class. From outside: Circle.PI or Math.PI. In real Java code, constants are also declared final to prevent accidental changes — that’s a refinement for later.

When to Use Each

Situation Use
The method needs to read or change this object’s fields instance method
The method is a pure utility — only needs its parameters static method
Each object should track its own value instance field
All objects should share one value (counter, constant) static field

Quick test: Can the method be written without ever mentioning any object? → static. Does it need “this” object’s data? → instance.

Walk through the decision table with concrete examples: area() needs this rectangle’s width and height → instance. gradeToLetter(int g) only needs the integer → static. name, grade — each student has their own → instance. totalCreated — one number for all students → static. Drill this with a few more examples until the decision becomes automatic.

Code Example

class BankAccount {
    static int totalAccounts = 0;         // shared counter
    static double interestRate = 0.03;    // shared constant

    String owner;
    double balance;

    BankAccount(String owner, double openingBalance) {
        this.owner   = owner;
        this.balance = openingBalance;
        totalAccounts++;
    }

    void applyInterest() {
        balance = balance + balance * interestRate;  // uses static field
    }

    void printInfo() {
        IO.println(owner + ": $" + balance);
    }

    static void printTotalAccounts() {
        IO.println("Accounts open: " + totalAccounts);
    }
}
BankAccount a = new BankAccount("Alice", 1000);
BankAccount b = new BankAccount("Bob",   500);
a.applyInterest();
a.printInfo();                       // Alice: $1030.0
BankAccount.printTotalAccounts();    // Accounts open: 2

This example shows all four combinations: static field (totalAccounts, interestRate), instance fields (owner, balance), instance methods (applyInterest, printInfo), static method (printTotalAccounts). Walk through what changes when a second account is created: totalAccounts goes to 2, but each account’s balance is independent. interestRate is the same for all accounts — changing BankAccount.interestRate to 0.05 would affect every future applyInterest() call.

Common Mistakes

Warning

Accessing an instance field from a static method

static void print() { IO.println(name); }  // ✗ — which object's name?

Static methods have no this. They can only use parameters and other static members.

Warning

Calling an instance method without an object

class Foo { void bar() { } }
Foo.bar();   // ✗ — bar() is an instance method, not static

Use new Foo().bar() or store an object first.

Warning

Making everything static “just to be safe” If every method is static, you’re not doing OOP — you’re just using a class as a namespace. Reserve static for methods that genuinely have no object state to read.

The first mistake produces the compiler error “non-static variable cannot be referenced from a static context” — one of the most common errors beginners see. Reading the error carefully: “non-static” = instance field, “static context” = inside a static method. The fix is always the same: either make the method instance (remove static), or pass the data as a parameter instead of reading a field.
