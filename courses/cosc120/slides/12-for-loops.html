for Loops

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Write a for loop and identify its three components: initializer, condition, and update
  • Write accumulator loops that compute a sum, product, or count using for
  • Combine a for loop with if/else inside the body to filter or classify values
  • Convert between while and for loops for the same problem
  • Choose between while and for for a given problem and justify the choice

A Familiar Problem

Last lecture we wrote this countdown:

int count = 5;          // initialize
while (count >= 1) {    // condition
    IO.println(count);
    count = count - 1;  // update
}

The three parts — initialize, condition, update — are spread across three different places.

Java has a second kind of loop that keeps all three in one line.

Callback to deck 11. Students already know while loops. The for loop is not a new idea — it’s a more compact way to write the same thing when you know how many iterations you need. Frame it as syntactic convenience first, not a new concept.

The for Loop

for (initialize; condition; update) {
    // body
}

The countdown, rewritten:

for (int count = 5; count >= 1; count = count - 1) {
    IO.println(count);
}

Same result. Same three parts. Everything in one place.

Show the mapping explicitly: what was on line 1 is now the first slot, what was in the while() is the second slot, what was at the bottom of the body is the third slot. The body is the only thing that didn’t move.

How for Executes — The Order

for (int i = 1; i <= 3; i = i + 1) {
    IO.println(i);
}

Java follows this exact sequence:

  1. Initialize once: int i = 1
  2. Check condition: i <= 3 → true, so run body
  3. Run body: IO.println(i)
  4. Update: i = i + 1
  5. Check condition again: repeat from step 2

The update happens after the body, before the next condition check.

Walk through this sequence verbally while pointing to each part of the for header. Students get confused about when the update fires. It is NOT the first thing that happens — it fires AFTER the body runs, then control goes back to the condition check. Initialize fires ONLY once, at the very start.

Tracing a for Loop

for (int i = 1; i <= 4; i = i + 1) {

}

Same variable table technique from deck 11 — identical skill, different loop syntax. Emphasize: the table doesn’t care whether it’s a while or a for; the loop mechanics are the same.

Shorthand: i++

i = i + 1 is so common that Java has a shorthand:

Long form Shorthand
i = i + 1 i++
i = i - 1 i--

So the countdown can be written:

for (int i = 5; i >= 1; i--) {
    IO.println(i);
}

Note

i++ and i-- work inside for updates only. Do not use them mid-expression until you understand precedence — keep it in the update slot for now.

Introduce i++ now so students can read real code. Many textbooks and examples use it. But caution against using it in complex expressions — just the update slot is safe and readable for beginners.

Accumulator with for

Sum of 1 through 10:

int sum = 0;

for (int i = 1; i <= 10; i++) {
    sum = sum + i;
}

IO.println("Sum: " + sum);   // Sum: 55

Product of 1 through 5 (5! = 120):

int product = 1;             // identity for multiplication

for (int i = 1; i <= 5; i++) {
    product = product * i;
}

IO.println("5! = " + product);   // 5! = 120

Same accumulator pattern from deck 11, now written with for. Point out: sum starts at 0 (identity for addition), product starts at 1 (identity for multiplication). Ask students: “Why would starting product at 0 be wrong?” Answer: everything multiplied by 0 is 0.

for with if Inside

Count how many numbers from 1 to 20 are divisible by 3:

int count = 0;

for (int i = 1; i <= 20; i++) {
    if (i % 3 == 0) {
        count = count + 1;
    }
}

IO.println("Divisible by 3: " + count);   // 6

The if filters — the loop visits every value, but only some update the counter.

This is the classify/filter pattern: the loop iterates over a range, and the if decides whether each value “qualifies.” Students will use this constantly — e.g., count how many grades are passing, how many strings match a pattern, etc. The % operator (modulo) is new here; define it if it hasn’t been seen yet: i % 3 == 0 means i divides evenly by 3.

while vs for — Side by Side

Same program, two syntaxes:

while

int i = 1;
while (i <= 5) {
    IO.println(i);
    i++;
}

for

for (int i = 1; i <= 5; i++) {
    IO.println(i);
}

Both produce identical output. They are interchangeable — a matter of style and clarity.

Show the mechanical equivalence. Then lead into the next slide which gives students a decision rule. The goal is not “for is better than while” but “for is more natural when you know the count up front.”

When to Use Each

Situation Prefer
You know exactly how many iterations you need for
You’re counting from A to B for
You’re stepping through a range of numbers for
You’re waiting for user input or an event while
The stop condition depends on what happens inside the loop while
Sentinel loops (“repeat until the user types ‘quit’”) while

Rule of thumb: if you can write the three parts (init, condition, update) before you know what the body does, use for. If the body needs to run first to know whether to stop, use while.

This decision rule is the practical payoff of teaching both loops. Drill it: “for = count-controlled; while = event-controlled.” Sentinel loops are the canonical while use case — the stop condition depends on what the user types, which you can’t know in advance.

Code Example

void printTable(int n) {
    IO.println("Multiplication table for " + n + ":");
    for (int i = 1; i <= 10; i++) {
        IO.println(n + " × " + i + " = " + (n * i));
    }
}

void main() {
    printTable(7);
}

Output:

Multiplication table for 7:
7 × 1 = 7
7 × 2 = 14
...
7 × 10 = 70

A clean, self-contained example that combines methods with parameters (deck 09) and a for loop. Ask: “Could we use a while loop here instead?” Yes — but for is cleaner because we know we always want exactly 10 rows. This reinforces the while vs for decision.

Common Mistakes

Warning

Semicolons, not commas for (int i = 0; i < 5; i++) — the three parts are separated by ; not ,.

Warning

Off-by-one (again) i < 5 runs 5 times (0–4). i <= 5 runs 6 times (0–5). Trace the last iteration.

Warning

Modifying the loop variable inside the body Changing i inside the body in addition to the update makes the loop very hard to reason about. Put all updates in the update slot.

Warning

Using i after the loop int i declared in the for header only exists inside the loop. It disappears after the closing }.

The scoping mistake (last one) previews deck 10’s scope concept in a new context. i declared in the for header is local to the loop — another bubble. Students will hit this when they try to use i after the loop and get a “cannot find symbol” error.

    int i = 10;
while (i >= 1) {
    IO.println(i);
    i = i - 2;

  4. Write a for loop that counts how many integers from 1 to 100 are divisible by both 3 and 5. Print the count.

  5. Trace the following loop and state what it prints:

    int result = 1;
for (int i = 1; i <= 5; i++) {
    result = result * 2;
}
IO.println(result);
