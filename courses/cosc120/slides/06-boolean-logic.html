Boolean Expressions — A Quick Recap

Recap from last lecture: a boolean expression is anything that evaluates to true or false. Relational operators (< > <= >= == !=) produce boolean results. This lecture extends that: what if we need a condition that combines two checks? We already say things like “if you are 16 and have a license, you can drive” — today we learn to write that in Java. Set up the need before introducing the operators.

Last lecture: a condition is an expression that produces true or false.

score >= 60       // true or false
name.equals("Alice")  // true or false
temperature < 32  // true or false

Sometimes one condition is not enough.

We say things like:

  • “You can drive if you are 16 and have a license.”
  • “You get a discount if you are a student or a senior.”
  • “The alarm triggers if it is not disarmed.”

Java has three operators for exactly this: &&, ||, and !.

The && Operator — AND

Both conditions must be true. Walk through the English examples first — students already reason this way. Then show the Java translation. The Venn diagram with the intersection highlighted is the most intuitive visual. The mini truth table shows all four combinations. Mention short-circuit evaluation only briefly: if the first condition is false, Java does not even check the second. This is a “fun fact” at this stage, not something students need to memorize.

&& means AND — both conditions must be true for the whole expression to be true.

English → Java:

English Java
“16 or older and has a license” age >= 16 && hasLicense
“Score above 60 and homework submitted” score > 60 && homeworkDone
“Temperature below 32 and it is snowing” temp < 32 && isSnowing
“Price over $50 and you have a coupon” price > 50 && hasCoupon

Truth table for &&:

A B A && B
true true true
true false false
false true false
false false false

&& is only true when both sides are true.

int age = 20;
boolean hasLicense = true;

if (age >= 16 && hasLicense) {
    IO.println("You may drive.");
}

The || Operator — OR

At least one condition must be true. The English examples help ground it: a discount for students OR seniors — either one qualifies. The Venn diagram for OR is the union of both circles. The key distinction from AND: with OR, both sides being true is still fine — only “both false” produces false. Walk through the truth table. A common mistake: students think OR means “one or the other but not both” — like in everyday English. In Java (and logic), OR means “at least one.”

|| means OR — at least one condition must be true.

English → Java:

English Java
“Student or senior” isStudent \|\| isSenior
“Rainy or below 40°F” isRaining \|\| temp < 40
“Score is 0 or answer is blank” score == 0 \|\| answer.equals("")
“Monday or Wednesday or Friday” day.equals("Mon") \|\| day.equals("Wed") \|\| day.equals("Fri")

Truth table for ||:

A B A \|\| B
true true true
true false true
false true true
false false false

|| is only false when both sides are false.

boolean isStudent = false;
boolean isSenior  = true;

if (isStudent || isSenior) {
    IO.println("Discount applied.");   // runs — isSenior is true
}

Note

In everyday English, “or” sometimes means “one or the other, but not both.” In Java, || means “at least one” — both being true is also fine.

The ! Operator — NOT

NOT flips the value: true becomes false, false becomes true. The English translations are straightforward — “not logged in,” “not raining,” “not game over.” Show the truth table (just two rows). Common use: checking for the absence of something. Also: !condition is cleaner than condition == false, which students sometimes write instead.

! means NOT — it flips true to false and false to true.

English → Java:

English Java
“Not logged in” !isLoggedIn
“Not raining” !isRaining
“Game is not over” !isGameOver
“Name does not equal Alice” !name.equals("Alice")

Truth table for !:

A !A
true false
false true 
boolean isRaining = false;

if (!isRaining) {
    IO.println("Good day for a walk!");   // runs — !false is true
}

boolean isLoggedIn = false;

if (!isLoggedIn) {
    IO.println("Please log in first.");   // runs
}

Tip

!condition is cleaner than writing condition == false. Use ! instead.

Combining Operators

Now that students know each operator individually, show how to combine them. Walk through several examples — one condition at a time. Precedence: ! is evaluated first, then &&, then ||. Parentheses override everything and are always clearer. Stress the parentheses habit: when in doubt, add parentheses. Compound conditions can get confusing fast; explicit parentheses make the intent clear and the bug easier to find.

You can combine &&, ||, and ! to express complex conditions.

Examples:

// Must be 18+ AND (student OR senior)
age >= 18 && (isStudent || isSenior)

// Temperature is extreme (very cold OR very hot)
temp < 10 || temp > 100

// Eligible if NOT banned AND has enough credits
!isBanned && credits >= 3

// Pass if exam score is 60+ AND (homework done OR extra credit earned)
examScore >= 60 && (homeworkDone || extraCredit)

Precedence — order of evaluation:

  1. ! first (like a minus sign in front of a number)
  2. && next
  3. || last
// Without parentheses:
a || b && c     // means: a || (b && c)

// Much clearer with parentheses:
a || (b && c)   // same result, but obvious
(a || b) && c   // different result!

Tip

When combining && and || — always use parentheses. The precedence rules are subtle. Parentheses make your intent clear and prevent bugs.

The else if Chain

else if lets you check multiple mutually exclusive cases in sequence. Java evaluates from top to bottom and stops at the first condition that is true. Only one branch ever runs — and once a branch runs, all subsequent else if and else branches are skipped. The grade classifier is the canonical example: score >= 90 is A, score >= 80 is B, etc. This also sets up the ordering problem perfectly, which gets its own slide next.

if/else handles two cases. What if there are more?

English: “If score is 90 or above → A. If 80 or above → B. If 70 or above → C. If 60 or above → D. Otherwise → F.”

if (score >= 90) {
    IO.println("A");
} else if (score >= 80) {
    IO.println("B");
} else if (score >= 70) {
    IO.println("C");
} else if (score >= 60) {
    IO.println("D");
} else {
    IO.println("F");
}

Java checks from top to bottom and stops at the first true condition.

Only one branch ever runs — never two, never zero.

score First true condition Output
95 score >= 90 A
83 score >= 80 B
71 score >= 70 C
60 score >= 60 D
45 none — else runs F

Ordering else if Conditions

The ordering of else if branches is critical and one of the most common mistakes. If the conditions are not ordered correctly, some branches become unreachable — they will never run because a less specific condition caught the case first. Show the WRONG version first, trace through it, and let students figure out why every passing grade comes out as D. Then show the fix. The rule: when conditions overlap, put the most specific (most restrictive) condition first.

The order of branches matters — a lot.

What happens if we reverse the grade classifier?

// WRONG — conditions in the wrong order
if (score >= 60) {
    IO.println("D");         // catches everyone who passes!
} else if (score >= 70) {
    IO.println("C");         // unreachable — score >= 70 already caught above
} else if (score >= 80) {
    IO.println("B");         // unreachable
} else if (score >= 90) {
    IO.println("A");         // unreachable
} else {
    IO.println("F");
}

If score is 95: the first condition 95 >= 60 is true → prints "D" → done. The A, B, and C branches never run.

The rule: put the most specific condition first.

score >= 90 is more specific than score >= 60. It covers fewer cases. Put it first so it has the chance to match.

// CORRECT — most specific first
if (score >= 90) {         // catches only 90–100
    IO.println("A");
} else if (score >= 80) {  // catches only 80–89
    IO.println("B");
} ...

Nested Conditionals

Sometimes a condition only makes sense to check after another condition has already passed. Example: you can only check whether someone has a ticket if they are already old enough to attend. An if inside another if handles this. Key readability point: indentation reveals the nesting. Each level of nesting is one more indent. Warn against deep nesting — more than two levels deep is usually a sign that the logic should be reorganized. The else if chain is often a cleaner alternative.

Sometimes a check only makes sense after a previous condition has already passed.

void main() {
    int age     = Integer.parseInt(IO.readln("Your age: "));
    String ticket = IO.readln("Do you have a ticket? (yes/no) ");

    if (age >= 18) {
        // only check ticket if they are old enough
        if (ticket.equals("yes")) {
            IO.println("Welcome! Enjoy the show.");
        } else {
            IO.println("You need a ticket to enter.");
        }
    } else {
        IO.println("You must be 18 or older to attend.");
    }
}

The inner if only runs when the outer condition (age >= 18) is already true.

Indentation reveals the structure — each level of nesting is one indent deeper.

Warning

Avoid nesting more than two levels deep. Deeply nested code is hard to read and easy to get wrong. Often, else if or compound conditions with && are a cleaner solution.

Nested if vs else if — Which to Use?

This is a design decision, not a syntax lesson. else if is the right tool when the cases are mutually exclusive and at the same level — letter grades from a score, day of the week, season from a month. Nested if is the right tool when one condition is a prerequisite for another — you can only be eligible for the upgrade if you are already a member; you can only check the balance if the account exists. The over-nesting mistake: beginners often reach for nested if when else if would be simpler and clearer. Show both solutions to the same problem.

Two patterns — different jobs:

else if — parallel cases

Cases are at the same level. At most one applies.

// What letter grade?
if (score >= 90) {
    IO.println("A");
} else if (score >= 80) {
    IO.println("B");
} else if (score >= 70) {
    IO.println("C");
} else {
    IO.println("D or F");
}

One score → one grade. Cases are independent.

Nested if — prerequisite check

One condition must pass before the next one even makes sense.

// Are they eligible for a bonus?
if (isEmployee) {
    if (yearsWorked >= 5) {
        IO.println("Eligible for bonus.");
    } else {
        IO.println("Not enough years.");
    }
} else {
    IO.println("Not an employee.");
}

Must be an employee first. Then check years.

Tip

Ask yourself: are the cases side by side (different values of the same thing)? Use else if. Is one condition a prerequisite for another? Use nested if.

Code Example — Event Admission

A complete program that combines && and || with an else if chain. The scenario: a venue with age rules and a VIP option. Walk through several inputs. Trace through with the class — which conditions evaluate first? Which branch runs? This also shows that compound conditions with && can replace one level of nesting.

Problem: A venue admits guests if they are 21 or older, OR if they are 18 or older and have a VIP pass. Anyone under 18 is not admitted regardless.

void main() {
    int age    = Integer.parseInt(IO.readln("Your age: "));
    String vip = IO.readln("VIP pass? (yes/no) ");
    boolean hasVip = vip.equals("yes");

    if (age < 18) {
        IO.println("Not admitted — must be at least 18.");
    } else if (age >= 21 || hasVip) {
        IO.println("Welcome! Come on in.");
    } else {
        IO.println("Must be 21 or older without a VIP pass.");
    }
}

Trace through three inputs:

age hasVip First true branch Output
16 no age < 18 Not admitted
19 yes age >= 21 \|\| hasVip Welcome!
19 no else Must be 21…
25 no age >= 21 \|\| hasVip Welcome!

Common Mistakes

Four mistakes that appear frequently in this unit. The precedence mistake (mixing && and || without parentheses) produces wrong results that compile fine — hardest to spot. The ordering mistake causes unreachable branches. The off-by-one in else if is subtle (>= vs > for grade boundaries). Using nested if when else if would be cleaner makes code harder to read.

1. Mixing && and || without parentheses

// Intended: (isStudent || isSenior) && hasId
// Actual:   isStudent || (isSenior && hasId)  ← different!
if (isStudent || isSenior && hasId) { ... }

// Fix — always parenthesize when mixing:
if ((isStudent || isSenior) && hasId) { ... }

2. else if conditions in the wrong order — unreachable branches

if (score >= 60) { IO.println("D"); }        // too broad — catches everyone
else if (score >= 90) { IO.println("A"); }   // unreachable!

// Fix — most specific first:
if (score >= 90) { IO.println("A"); }
else if (score >= 60) { IO.println("D"); }

3. Using > instead of >= at grade boundaries

if (score > 90) { IO.println("A"); }   // misses exactly 90
if (score >= 90) { IO.println("A"); }  // ✓

4. Deep nesting when else if or && would be cleaner

// Overly nested — hard to follow
if (age >= 18) {
    if (score >= 60) {
        if (homeworkDone) {
            IO.println("Pass");
        }
    }
}

// Cleaner with &&
if (age >= 18 && score >= 60 && homeworkDone) {
    IO.println("Pass");
}
