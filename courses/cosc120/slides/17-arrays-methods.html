Passing Arrays to Methods

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Declare and call a method that takes an int[] parameter and returns a computed value
  • Explain that arrays are passed by reference — changes inside the method persist in the caller’s array
  • Contrast array parameters (reference) with primitive parameters (copied) and predict the outcome of each
  • Write void methods that modify an array in place (fill, double elements, replace)
  • Compose array methods — call one from another and use the return value as an argument

Arrays as Parameters

Arrays can be passed to methods just like any other type:

void printAll(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        IO.println(arr[i]);
    }
}

int sum(int[] arr) {
    int total = 0;
    for (int i = 0; i < arr.length; i++) { total += arr[i]; }
    return total;
}

void main() {
    int[] scores = {88, 74, 91, 65, 78};
    printAll(scores);
    IO.println("Sum: " + sum(scores));
}

The parameter type is int[] — an array of integers.

The syntax is straightforward: write the type with brackets (int[]) followed by the parameter name. Students who mastered deck 09 (parameters) will find this familiar — it’s the same idea, just a different type. The interesting part is what happens inside the method when you modify the array, which the next slides address.

Two Ways to Pass Data

When you pass something to a method, Java has two strategies:

Photocopy

The method gets its own copy. Changes don’t affect the original.

Used for: int, double, boolean, char, String

Shared link

The method gets a link to the same thing. Changes affect the original.

Used for: arrays (and objects)

The photocopy/shared-link analogy works for almost every student. A photocopy: you can mark it up however you want; your friend’s original is untouched. A shared Google Doc link: your edit appears in their browser immediately. Arrays behave like the shared link. Primitives behave like the photocopy. Spend time here — this is one of the most surprising concepts in the course.

Primitives Are Copied

Changes to a primitive parameter do not affect the caller:

void tryToDouble(int n) {
    n = n * 2;            // changes the LOCAL copy only
    IO.println("Inside: " + n);   // 10
}

void main() {
    int x = 5;
    tryToDouble(x);
    IO.println("Outside: " + x);   // still 5!
}

Output:

Inside: 10
Outside: 5

x in main is unaffected — tryToDouble received a copy of the value 5.

Walk through this example carefully. When tryToDouble(x) is called, Java copies the value 5 into the parameter n. The method doubles its own copy (n becomes 10), but x in main still holds 5. n and x are two separate variables — changing one has no effect on the other.

Arrays Are Passed by Reference

Changes to an array parameter do affect the caller’s array:

void doubleAll(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        arr[i] = arr[i] * 2;     // modifies the original
    }
}

void main() {
    int[] scores = {10, 20, 30};
    doubleAll(scores);
    IO.println(scores[0]);   // 20 — the original was changed!
    IO.println(scores[1]);   // 40
    IO.println(scores[2]);   // 60
}

doubleAll and main are looking at the same array. The method’s changes are permanent.

This surprises students almost every time. The key question to ask: “Did we return anything from doubleAll?” No — it’s void. Yet main’s array changed. That’s because both the method and main hold the same link to the same memory. Modifying arr[i] inside the method modifies the underlying data, which main’s scores variable also points to.

void test(int n, int[] arr) {
    n = 99;           // no effect on caller's variable
    arr[0] = 99;      // DOES affect caller's array
}

The table summarizes the rule. After showing the table, trace the test() example: n is a local copy (changing it does nothing outside), arr is a shared link (changing arr[0] changes the original). Ask students: “After calling test(x, scores), what is x? What is scores[0]?” x is unchanged; scores[0] is 99.

Returning a Value Computed from an Array

Methods can also read an array and return a result without modifying it:

double average(int[] arr) {
    int sum = 0;
    for (int i = 0; i < arr.length; i++) {
        sum += arr[i];
    }
    return (double) sum / arr.length;
}

boolean allPassing(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] < 60) { return false; }
    }
    return true;
}

void main() {
    int[] scores = {88, 74, 91, 65, 78};
    IO.println("Average: " + average(scores));
    IO.println("All passing: " + allPassing(scores));
}

These methods read the array but don’t change it. average uses the accumulator pattern and returns a double. allPassing uses an early-return pattern: as soon as it finds one failing grade, it returns false immediately without looking at the rest. If no failure is found after examining every element, it returns true.

void Methods That Modify In Place

Fill an array with a value:

void fill(int[] arr, int value) {
    for (int i = 0; i < arr.length; i++) {
        arr[i] = value;
    }
}

Replace negatives with zero:

void clampToZero(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        if (arr[i] < 0) { arr[i] = 0; }
    }
}

These methods are void — they don’t need to return anything because the caller’s array is already changed.

These are clean, useful examples of in-place modification methods. fill is similar to Java’s own Arrays.fill(). clampToZero is a simple “clip” operation. The void return type is intentional — there is nothing to return because the entire purpose of the method is the side effect on the shared array. Ask students: if you wanted a version that didn’t modify the original, what would you need? (Answer: make a copy first — a preview of a future concept.)

Composing Array Methods

You can pass the return value of one method as an argument to another:

int[] doubled = {10, 20, 30};
doubleAll(doubled);                           // modifies doubled in place

IO.println("New average: " + average(doubled));   // pass array to another method

Or build a pipeline:

void main() {
    int[] scores = {88, 74, 91, 65, 78};

    IO.println("Before: avg = " + average(scores));
    clampToZero(scores);          // modifies scores
    fill(scores, 100);            // overwrites all with 100
    IO.println("After: avg = " + average(scores));
}

Composition is the payoff of writing methods. Each method does one thing cleanly; you combine them to build more complex behavior. The pipeline example shows in-place methods working in sequence — each one hands the (now-modified) array to the next. Students who built sum, average, min, max, and reverse in earlier worksheets now have a toolkit they can compose freely.

Code Example

void scaleScores(int[] arr, int bonus) {
    for (int i = 0; i < arr.length; i++) {
        arr[i] = arr[i] + bonus;
        if (arr[i] > 100) { arr[i] = 100; }   // cap at 100
    }
}

double average(int[] arr) {
    int sum = 0;
    for (int i = 0; i < arr.length; i++) { sum += arr[i]; }
    return (double) sum / arr.length;
}

void main() {
    int[] scores = {72, 85, 58, 91, 64};
    IO.println("Before avg: " + average(scores));    // 74.0
    scaleScores(scores, 10);
    IO.println("After avg:  " + average(scores));    // 82.0 (91+10 capped at 100)
}

scaleScores modifies in place (void), average reads without modifying (returns double). Calling average before and after scaleScores demonstrates that the array was actually changed. The cap at 100 is a real-world touch — curved grades don’t exceed 100.

Common Mistakes

Warning

Expecting a modified primitive to persist If a method changes int n, the caller’s variable is unaffected. Primitives are copied.

Warning

Accidentally modifying an array you meant to leave alone If your method reads the array but a bug writes to it, the caller’s data is silently corrupted. Double-check that read-only methods don’t do any arr[i] = ... assignments.

Warning

Forgetting .length when passing an array between methods The array carries its length — you don’t need to pass it separately. arr.length works inside any method that received arr.

Warning

Returning an array index when you should return the value (or vice versa) Linear search returns the index. Sum returns the value. Be clear about which your method promises to return.

The second mistake is especially insidious because there’s no error message — the bug is silent. Write tests that print the caller’s array before and after any method call until the pass-by-reference behavior becomes second nature.

  2. Write int max(int[] arr) that returns the largest element. Then write void replaceMax(int[] arr, int newVal) that finds the first occurrence of the maximum and replaces it with newVal. Call both in sequence.

  3. Predict the output:

    n = 0;

void main() {
    int x = 42;
    int[] data = {10, 20, 30};
