Instance Methods

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Write an instance method inside a class body that reads fields and returns a computed value
  • Write a void instance method that modifies one or more fields (with or without a parameter)
  • Write a boolean method that computes a predicate from an object’s fields (e.g., isPassing(), isSquare())
  • Call an instance method on an object using dot notation — obj.method() or obj.method(arg)
  • Compose two or more instance methods in a single class to solve a multi-step problem

Two Kinds of Methods

So far you have written standalone methods (deck 08):

void bark(String name) {      // must receive name as a parameter
    IO.println(name + ": Woof!");
}

Today you write instance methods — methods that live inside a class and already know the object’s state:

class Dog {
    String name;

    void bark() {             // no parameter needed — name is a field
        IO.println(name + ": Woof!");
    }
}

The difference: rex.bark() versus bark("Rex").

This is the key conceptual jump. Standalone methods (decks 08–10) know nothing about the world unless you pass them data. Instance methods live inside an object and can see every field without being told. “Rex, bark!” — Rex already knows his own name. You don’t have to hand it to him. This is what “bundling data with behavior” actually means in code.

Defining an Instance Method

An instance method is written inside the class body, just like the constructor — but without the constructor name rules:

class Student {
    String name;
    int grade;

    Student(String name, int grade) {
        this.name  = name;
        this.grade = grade;
    }

    void greet() {                           // ← instance method
        IO.println("Hi, I'm " + name + "!");
    }
}
  • Defined inside { } of the class
  • Can read and modify any field directly (no this. needed when there’s no name clash)
  • Called on an object: alice.greet()

Walk through the anatomy: the greet() method is defined inside class Student, so it belongs to every Student object. When alice.greet() is called, Java runs the method body with name already set to “Alice” — it accesses the field of the object greet() was called on. There’s no name clash here so this.name is fine as just name.

The Method Sees Its Object’s Fields

When an instance method runs, it automatically sees the fields of the object it was called on:

Student alice = new Student("Alice", 88);
Student bob   = new Student("Bob",   74);

alice.greet();   // Hi, I'm Alice!
bob.greet();     // Hi, I'm Bob!

Same method body — different output — because name resolves to a different field each time.

This is the magic of instance methods — one definition, personalized execution. The method code is shared, but the data each invocation reads is unique to the object it was called on. Ask: “If we add a third student carol and call carol.greet(), what prints?” They should be able to answer immediately.

Methods That Return a Value

Instance methods can compute and return values from fields:

class Rectangle {
    int width;
    int height;

    Rectangle(int width, int height) {
        this.width  = width;
        this.height = height;
    }

    int area() {
        return width * height;
    }

    int perimeter() {
        return 2 * (width + height);
    }
}
Rectangle r = new Rectangle(4, 6);
IO.println(r.area());       // 24
IO.println(r.perimeter());  // 20

area() and perimeter() read the object’s own fields and return computed values. No parameters are needed because the data (width, height) is already inside the object. Compare this to deck 09 where you’d write area(int w, int h) — now the dimensions travel with the rectangle and don’t need to be passed in.

void Methods That Modify Fields

Instance methods can also change the object’s state:

class BankAccount {
    String owner;
    double balance;

    BankAccount(String owner, double balance) {
        this.owner   = owner;
        this.balance = balance;
    }

    void deposit(double amount) {
        balance = balance + amount;
    }

    void withdraw(double amount) {
        balance = balance - amount;
    }

    void printBalance() {
        IO.println(owner + "'s balance: $" + balance);
    }
}
BankAccount acct = new BankAccount("Alice", 100.0);
acct.deposit(50.0);
acct.withdraw(30.0);
acct.printBalance();   // Alice's balance: $120.0

deposit() and withdraw() modify the balance field directly — no return value needed because the purpose is the side effect on the object’s state. printBalance() reads fields without modifying them. Walk through the three method calls: after deposit(50), balance = 150; after withdraw(30), balance = 120; printBalance reads 120.

Boolean Predicate Methods

A predicate method asks a yes/no question about the object’s state and returns boolean:

class Student {
    String name;
    int grade;

    Student(String name, int grade) {
        this.name  = name;
        this.grade = grade;
    }

    boolean isPassing() {
        return grade >= 60;
    }

    boolean hasHonors() {
        return grade >= 90;
    }
}
Student alice = new Student("Alice", 88);
IO.println(alice.isPassing());   // true
IO.println(alice.hasHonors());   // false

Predicate methods are named as questions (isPassing, hasHonors, isEmpty, isValid). They return boolean and are often used in if statements: if (alice.isPassing()) { … }. Students have already seen .equals() and .equalsIgnoreCase() on Strings — those are boolean predicate methods on the String class.

Composing Instance Methods

Instance methods can call each other and use each other’s results:

class Student {
    String name;
    int grade;

    Student(String name, int grade) {
        this.name  = name;
        this.grade = grade;
    }

    boolean isPassing() { return grade >= 60; }

    String letterGrade() {
        if (grade >= 90) { return "A"; }
        if (grade >= 80) { return "B"; }
        if (grade >= 70) { return "C"; }
        if (grade >= 60) { return "D"; }
        return "F";
    }

    void printReport() {
        IO.println(name + ": " + grade + " (" + letterGrade() + ")");
        if (!isPassing()) {
            IO.println("  ⚠ Needs improvement.");
        }
    }
}

printReport() calls letterGrade() and isPassing() — both methods of the same class. Inside an instance method, calling another instance method of the same class doesn’t need dot notation (no this.letterGrade() needed, though that also works). The methods build on each other, keeping each one short and focused.

Calling Instance Methods

Always call instance methods on an object using dot notation:

Student alice = new Student("Alice", 88);

alice.printReport();     // ✓
alice.isPassing();       // ✓ (result discarded — use in if or assignment)

boolean passing = alice.isPassing();  // ✓ store result
if (alice.hasHonors()) { ... }        // ✓ use in condition

printReport();           // ✗ compile error — which student?

The object before the dot is the receiver — the object whose fields the method sees.

“Which student?” is the right question when students forget the dot. The method needs to know whose fields to read — you must tell it by specifying the object. This contrasts with standalone methods (decks 08–10) where you just write the method name. Instance methods need a receiver.

Code Example

class Rectangle {
    int width;
    int height;

    Rectangle(int w, int h) {
        this.width  = w;
        this.height = h;
    }

    int area()      { return width * height; }
    int perimeter() { return 2 * (width + height); }
    boolean isSquare() { return width == height; }

    void describe() {
        IO.println(width + "×" + height +
            " | area=" + area() +
            " | perimeter=" + perimeter() +
            " | square=" + isSquare());
    }
}

void main() {
    Rectangle r1 = new Rectangle(4, 6);
    Rectangle r2 = new Rectangle(5, 5);
    r1.describe();
    r2.describe();
}

A clean, self-contained example. Walk through r1.describe(): area() returns 24, perimeter() returns 20, isSquare() returns false (4 ≠ 6). Then r2.describe(): area() = 25, perimeter() = 20, isSquare() = true (5 == 5). Point out that describe() composes the other three methods — it doesn’t duplicate their logic.

Common Mistakes

Warning

Calling an instance method without an object isPassing() alone is a compile error outside the class. Inside the class (from another instance method), it works — Java assumes this.isPassing(). Outside, you must specify which object: alice.isPassing().

Warning

Passing fields as parameters to an instance method int area(int width, int height) — the fields are already available; you don’t need to pass them. int area() is correct.

Warning

Calling an instance method on the class name, not an object Student.isPassing() — compile error. The class is the blueprint; you need an instance: alice.isPassing().

Warning

Forgetting to assign the return value alice.area() does nothing useful if you don’t store or print the result. Use: IO.println(alice.area()) or int a = alice.area().
