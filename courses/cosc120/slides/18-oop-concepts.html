What Is an Object?

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Distinguish a class (blueprint) from an object (instance) and use new ClassName() to create an object
  • Access and modify an object’s state using dot notation (obj.field = value)
  • Invoke an object’s behavior by calling its methods (obj.method()) and observe how method calls change state
  • Create multiple independent objects from the same class and predict each object’s state after a sequence of operations
  • Explain why grouping related fields and methods into a class leads to clearer, more organized code

The Problem Without Objects

Imagine tracking three students’ names and grades:

String name0 = "Alice";  int grade0 = 88;
String name1 = "Bob";    int grade1 = 74;
String name2 = "Carol";  int grade2 = 91;

These six variables are clearly related — but Java doesn’t know that. You can’t pass “a student” to a method. You can’t say “print student 1.”

The need: a way to bundle related data (and the actions on it) into one named thing.

This is the same motivation as arrays, but taken further. Arrays solved “many values of the same type.” Objects solve “many related values of different types.” A student isn’t just a grade OR a name — they’re both together. OOP lets you represent that.

Everything Around You Is an Object

Look around the room. Every physical thing has:

  • Properties — things that describe it (color, size, model, charge)
  • Behaviors — things it can do (play, charge, ring, open)
Thing Properties Behaviors
Phone brand, battery%, color call(), text(), takePicture()
Dog name, breed, age bark(), eat(), fetch()
Bank account owner, balance deposit(), withdraw()

Programming objects work the same way. A class defines the properties and behaviors. An object is one specific instance of that class.

This is the core OOP intuition. Students should nod — they already think about the world in terms of things with properties and behaviors. The job of OOP is to let them bring that mental model directly into code. Don’t rush past this slide; it’s the entire foundation.

Class vs Object

Class = Blueprint

The template that defines what all dogs look like and can do.

One blueprint exists.

Dog
------
name
breed
age
------
bark()
birthday()

Object = Instance

A specific dog built from that blueprint.

Many objects can exist.

rex
------
name = "Rex"
breed = "Lab"
age = 3
luna
------
name = "Luna"
breed = "Poodle"
age = 1

The blueprint/house or cookie-cutter/cookie analogies both work here. The class is defined once. Objects (instances) are created from it as many times as needed — each one gets its own independent copy of the fields. Changing rex’s name has zero effect on luna’s name.

Cookie Cutter and Cookies

The cookie cutter (class) is made once.

Each cookie (object) is stamped out from it — same shape, but you can decorate each one differently.

Changing the decoration on one cookie does not affect the others.

Let students sit with this image. Some will say “but I could change all the cookies by changing the cutter!” — yes, that’s what changing the class definition does. But after they’re stamped out, the cookies are independent. Runtime state changes on one object don’t bleed into others.

A Simple Class

class Dog {
    String name;     // fields — the object's state
    String breed;
    int age;

    void bark() {    // methods — the object's behavior
        IO.println(name + " says: Woof!");
    }

    void birthday() {
        age = age + 1;
        IO.println(name + " is now " + age + "!");
    }
}
  • Fields (name, breed, age) — variables that live inside every Dog object
  • Methods (bark, birthday) — actions every Dog object can perform

This is the first class students see written in full. Keep it concrete: every Dog object will have its own name, breed, and age. The bark() method reads the object’s own name field — it “knows” who it is. You don’t pass the name in; the method finds it in the same object. This is state + behavior bundled together.

Creating an Object

Dog rex = new Dog();
Part Meaning
Dog The type — this variable holds a Dog
rex The variable name
new Dog() Create a brand-new Dog object in memory

After this line, rex exists but has no name, breed, or age yet — those fields hold default values (null, null, 0).

Note

new is the keyword that creates an object. Every time you write new ClassName(), Java builds a fresh independent object.

Compare new Dog() to new int[5] — students have already seen new, just not with classes. The parallel is helpful: new creates something fresh in memory. The variable (rex) holds a reference (link) to that new object — just like arrays. This is why arrays behave like objects: they ARE objects.

Setting an Object’s State

Use dot notation to access and change fields:

Dog rex = new Dog();
rex.name  = "Rex";
rex.breed = "Labrador";
rex.age   = 3;

IO.println(rex.name);    // Rex
IO.println(rex.age);     // 3

The dot (.) means: “go into this object and find ___.”

rex.name — “the name field of the object that rex refers to.”

Dot notation is the fundamental syntax of OOP. Students already know obj.length() for arrays and str.length() for Strings — this is the same pattern. The dot is a selector: go into the object, find the thing named after the dot. Walk through each line and confirm what each IO.println produces.

Calling an Object’s Methods

Use dot notation to invoke behavior:

rex.bark();       // Rex says: Woof!
rex.birthday();   // Rex is now 4!
IO.println(rex.age);   // 4 — the field actually changed!

Methods can read and change the object’s own fields — that’s what makes them powerful.

birthday() didn’t need age passed as a parameter. It found age inside the same object.

This is the “behavior changes state” idea. birthday() modifies age — not a local copy, the actual field inside rex. That’s different from what primitive parameters do (deck 09). An object’s method has direct access to the object’s own state. This is what it means to bundle data and behavior together.

Multiple Independent Objects

Each object has its own separate copy of every field:

Dog rex  = new Dog();
rex.name = "Rex";
rex.age  = 3;

Dog luna = new Dog();
luna.name = "Luna";
luna.age  = 1;

rex.birthday();              // rex's age becomes 4
IO.println(luna.age);        // still 1 — luna is unaffected

rex and luna are built from the same Dog class but are completely independent.

This is the cookie image in code form. Changing rex’s age does not affect luna’s age because they are two separate objects in memory — two separate “cookies.” Walk through the exact sequence: rex.birthday() changes rex.age from 3 to 4; luna.age remains 1. Predict the output before running it.

Why OOP?

Without OOP:

String name0 = "Alice";  int grade0 = 88;
String name1 = "Bob";    int grade1 = 74;
// ... 28 more pairs for a class of 30

With OOP:

Student alice = new Student();
alice.name = "Alice";
alice.grade = 88;
// alice.letterGrade() — behavior comes with the data

OOP benefits: organization (related data and behavior live together), reuse (create as many students as you need), readability (the code mirrors the real world).

Bring it back to the opening motivation slide. OOP isn’t a trick — it’s a way to make programs that mirror how we already think about the world. “Give me a student” is something humans understand. Writing six variables for one student is not how humans think. OOP bridges that gap.
