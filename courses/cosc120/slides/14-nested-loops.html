Nested Loops

COSC120: Introduction to Computer Science I

Learning Outcomes

  • Write a nested loop with distinct inner and outer variables to produce two-dimensional output
  • Use IO.print inside the inner loop and IO.println at the end of each outer iteration to build 2D patterns
  • Reset and recompute an accumulator inside the outer loop using an inner loop (e.g., row sums, row max)
  • Trace a nested loop and determine the values of both loop variables and any accumulators at each step
  • Calculate the total number of inner-loop iterations and identify problems that require nested loops

The Clock Analogy

Think about how a clock works:

  • The hour hand (outer loop) moves once every 12 ticks of the minute hand
  • The minute hand (inner loop) completes one full revolution for every single tick of the hour hand

Nested loops work the same way: the inner loop runs completely for every single iteration of the outer loop.

The clock is a perfect physical analogy because every student has seen one. Spend time on this before showing any code — if they understand the clock, they understand nested loops. The key word is “completely”: the minute hand doesn’t pause at 30 waiting for the hour hand; it finishes 60 minutes before the hour advances.

What Is a Nested Loop?

A nested loop is a loop inside another loop:

for (int outer = 1; outer <= 3; outer++) {
    for (int inner = 1; inner <= 4; inner++) {
        IO.print("(" + outer + "," + inner + ") ");
    }
    IO.println();    // new line after each complete inner loop
}

Output:

(1,1) (1,2) (1,3) (1,4)
(2,1) (2,2) (2,3) (2,4)
(3,1) (3,2) (3,3) (3,4)
  • Outer loop controls rows (runs 3 times)
  • Inner loop controls columns (runs 4 times per row)

Point to the output and connect it back to the clock: when outer = 1, inner counts all the way from 1 to 4, then outer finally advances to 2. Note IO.print (no newline) vs IO.println (newline) — IO.print keeps building the same row; IO.println() at the end of the outer body starts a new line.

IO.print vs IO.println

Method Effect
IO.println(value) Prints value then moves to a new line
IO.print(value) Prints value but stays on the same line

Building a row one piece at a time:

IO.print("A");   // A
IO.print("B");   // AB
IO.print("C");   // ABC
IO.println();    // ABC  ← then newline

This is the pattern for nested-loop output: IO.print inside the inner loop, IO.println() in the outer loop body.

This is many students’ first encounter with IO.print. Make sure they understand that IO.print and IO.println are the same idea — IO.print just doesn’t advance to the next line. The empty IO.println() at the end of the outer body is the “carriage return” that starts the next row.

Tracing a Nested Loop

for (int row = 1; row <= 2; row++) {
    for (int col = 1; col <= 3; col++) {
        IO.print("* ");
    }
    IO.println();
}
row col Action
1 1 print *
1 2 print *
1 3 print *
1 — println (new line)
2 1 print *
2 2 print *
2 3 print *
2 — println (new line)

Output: * * * / * * *

Walk through the trace table row by row aloud. When col reaches 3 and increments to 4, the inner loop condition (col <= 3) becomes false, the inner loop exits, and println fires. Then row increments and the inner loop starts FRESH from col = 1. Students are often surprised that col resets — it’s because col is declared inside the outer loop, so it’s re-initialized every outer iteration.

Counting Total Iterations

Rule: total inner-loop iterations = outer iterations × inner iterations per outer

for (int i = 1; i <= 5; i++) {        // 5 outer iterations
    for (int j = 1; j <= 10; j++) {   // 10 inner iterations EACH
        // this body runs 5 × 10 = 50 times
    }
}
Outer range Inner range Total body executions
1 to 5 1 to 10 50
1 to 3 1 to 3 9
1 to n 1 to n n²

Note

Nested loops can get expensive fast. A 1000 × 1000 nested loop runs 1 000 000 times.

The n² observation is a preview of algorithmic complexity — don’t dwell on it, but worth naming. The practical warning: students sometimes accidentally write nested loops with huge ranges and wonder why their program seems frozen.

Star Patterns

A rectangle of stars (3 rows × 5 cols):

for (int row = 1; row <= 3; row++) {
    for (int col = 1; col <= 5; col++) {
        IO.print("* ");
    }
    IO.println();
}

A right triangle:

for (int row = 1; row <= 5; row++) {
    for (int col = 1; col <= row; col++) {   // inner limit = row
        IO.print("* ");
    }
    IO.println();
}
*
* *
* * *
* * * *
* * * * *

The triangle is the key insight: the inner loop’s upper bound doesn’t have to be a fixed number — it can be the outer variable. When row = 1, inner runs once. When row = 5, inner runs 5 times. This is a common worksheet exercise and a good mental stretch.

Accumulator Inside the Outer Loop

Goal: print the sum of each row in a multiplication table:

for (int row = 1; row <= 3; row++) {
    int rowSum = 0;       // reset for every new row

    for (int col = 1; col <= 4; col++) {
        int value = row * col;
        IO.print(value + "\t");
        rowSum = rowSum + value;
    }

    IO.println("  | sum = " + rowSum);
}

Output:

1  2  3  4   | sum = 10
2  4  6  8   | sum = 20
3  6  9  12  | sum = 30

The critical point: rowSum is declared INSIDE the outer loop (above the inner loop), so it resets to 0 at the start of each row. If rowSum were declared outside the outer loop, it would accumulate across all rows — a different answer entirely. This is another scope moment: where you declare the variable changes what it does.

When Do You Need Nesting?

Nested loops appear whenever the problem is two-dimensional:

Problem Outer loop Inner loop
Multiplication table Each row Each column
Seating chart Each row of seats Each seat in the row
Grid of pixels Each row of pixels Each pixel in the row
All pairs from two lists Each item in list A Each item in list B
Pattern of stars Each line Each character on the line

Ask yourself: “For each ___, do I need to repeat something across ___?”

The “for each … for each …” phrasing is a reliable signal that nested loops are needed. If students can articulate “for each row, for each column in that row, do X,” the code almost writes itself.

Code Example — Multiplication Table

void printMultiplicationTable(int size) {
    for (int row = 1; row <= size; row++) {
        for (int col = 1; col <= size; col++) {
            IO.print(row * col + "\t");
        }
        IO.println();
    }
}

void main() {
    printMultiplicationTable(5);
}

Output (size = 5):

1   2   3   4   5
2   4   6   8   10
3   6   9   12  15
4   8   12  16  20
5   10  15  20  25

The \t is a tab character — it aligns the columns. Clean, real output. Ask students: how many times does the inner body execute? 5 × 5 = 25. What would printMultiplicationTable(10) produce? A 10×10 table with 100 cells.

Common Mistakes

Warning

Reusing the same variable name for inner and outer for (int i ...) { for (int i ...) } — the inner i shadows the outer i. Use distinct names: row/col, i/j, outer/inner.

Warning

Forgetting IO.println() after the inner loop Without it, all rows print on one long line.

Warning

Declaring the accumulator outside the outer loop If rowSum = 0 is outside both loops, it never resets between rows. Declare it at the top of the outer loop body.

Warning

Off-by-one on the inner range When the inner limit depends on the outer variable (like the triangle), trace a couple of rows to confirm the count is right.

The first mistake (reusing i) sometimes doesn’t cause a compile error in all Java versions but always causes confusion. Using meaningful names like row/col sidesteps it entirely and makes code readable. The accumulator placement mistake is a direct consequence of scope, connecting back to deck 10.
